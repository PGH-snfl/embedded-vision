# 부품별 라벨 분리와 연결 제안 — 2026-10-22

## 구현한 동작

실사 사진의 **핀·선 끝점 검토 → 확대해서 핀과 배선 검토하기**에서 사용한다.

1. OCR 문자 영역을 선택한다. OCR은 사진에 인쇄된 문자를 읽는 기능이다.
2. 문자가 속한 부품 후보를 선택한다. 여러 영역이 겹치면 후보를 모두 보여 주며 사용자가 직접 소속을 판단한다.
3. 원문에서 분리한 이름 후보를 누른다. LCD의 `VSSVDDV0RSRWED0D1D2D3D4D5D6D7A`를 `VSS`, `VDD`, `V0`, …, `A`의 15개 후보로 제시한다. 원문에 없는 `K`를 추가하지 않는다.
4. 실제 핀 위치를 사진에서 찍고 근거를 입력한 뒤 저장한다. 이름은 INFERRED(추정), 데이터시트 핀 번호는 UNKNOWN(미확인)이다. OCR 원문의 어느 구간을 사용했는지도 근거로 남긴다.
5. 선 조각을 선택한다. 양 끝점 가까이에 지정 핀이 하나씩 있으면 두 핀을 선택란에 제안한다. 실제 접촉 여부 체크와 근거 입력은 사용자가 해야 한다.
6. 끝점 주변 핀이 없거나 여러 개면 이유를 표시한다. 이미 저장한 연결은 중복 저장 대신 기존 연결 검토로 안내한다.

핀을 저장한 뒤에도 선택한 문자와 부품을 유지하므로 같은 핀 열을 이어서 검토할 수 있다. 저장한 이름 후보는 표시하고 중복 입력을 막는다. 이름·부품을 바꾸면 이전 임시 핀 위치를 해제한다.

## 판단 범위

문자 분리는 관측 문자열에 대한 규칙 기반 보조 기능이다. 추가 AI 추론이나 데이터시트 pinout 생성은 하지 않는다. `D10`을 `D1`로 잘라 쓰지 않으며 `O/0`을 자동 교정하지 않는다. 해석할 수 없는 문자열은 그대로 보여 준다.

부품 영역 경계 근처(정규화 좌표 ±0.025)의 문자를 검토 후보에 포함하지만 소속을 확정하지 않는다. 문자 사각형 중심이나 분리한 글자의 위치를 실제 핀 좌표로 사용하지 않는다.

선 끝점에서 이미지 짧은 변의 4% 이내 핀을 검색한다. 핀이 여러 개면 자동 선택하지 않는다. 가까이 있다는 사실만으로 가려진 선을 연결하거나 실제 도통을 검증하지 않는다. 제안 생성 자체는 그래프·리비전을 변경하지 않는다.

## 실제 사진 결과

프로젝트 `e55f486bb02e4c1ca8bc1b75c022dee8`의 기존 r3을 사용했다. 모델을 재실행하지 않고 저장된 OCR·부품 영역·선 조각에 새 기능을 적용했다.

- LCD 문자열 소속 후보: LCD와 브레드보드의 경계 근처로 표시. 사용자 선택 필요.
- LCD 이름 후보 15개. 원문에 빠진 K는 제안하지 않음.
- 선 조각 3개는 모두 `MISSING_PIN`(실제 핀 위치 필요).
- 사용자 원본 그래프와 r3 유지. 임의 핀·전기적 연결 추가 없음.

따라서 이번 구현은 사진 검토와 연결 후보 입력을 돕는 단계다. 이 사진을 바로 조립 가능한 회로로 자동 복원한 것은 아니다.

## 검증

- 전체 테스트 **111개 통과**, 24.27초. KiCad 연결 대조·ERC·DRC 및 ngspice 예제 포함. 이전 검증에서 확인한 메모리 압박을 피하려고 시험 중 로컬 AI 모델을 잠시 내렸고, 시험 후 복구했다.
- 새 테스트 17개: 원문 구간 보존, 없는 이름 미생성, 긴 숫자 라벨 구분, 잘못 읽은 문자열 보존, 부품 소속 모호성, 다른 사진 배제, 다중 핀 자동 선택 방지, 기존 연결 중복 방지, 원문 구간 변조 거부 등.
- 실제 브라우저에서 LCD 이름 15개 표시와 이름 클릭 후 저장 비활성 상태를 확인했다.
- 분리된 합성 입력에서 이름 후보 클릭 → 실제 위치 지정 → 핀 저장 → 양쪽 핀 제안 → 사용자 확인 → INFERRED 연결 저장을 검증했다. 원문 `[0:3]: VSS` 근거가 남고 실제 핀 번호는 UNKNOWN을 유지했다. 기존 연결 재저장은 비활성화됐다.
- 합성 입력은 테스트용 임시 서버(8767)에서만 사용했다. 사용자 사진 결과와 섞지 않았다.
