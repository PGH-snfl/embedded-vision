# 생성된 회로의 실행·조작·3D 연결

2026-11-10. 현재 자동 설계 대상인 **Arduino UNO 한 대와 지원 부품**에 대해 생성 → 컴파일 → 기본 동작 시험 → 실행 → 사용자 조작 → 출력/3D 반응을 연결했다.

## 실제 실행 경로

1. 관측 구성품에 근거해 기능·선정 부품·연결·코드를 생성한다. 새 설계에서 비어 있는 알려진 모듈의 GND 핀은 공통 접지에 보완한다. 기존에 배선된 핀, 제어 핀과 코드는 변경하지 않는다. 보완 내용은 `simulation_repairs`로 분석 결과와 데이터시트에 남긴다.
2. 기존 격리 컴파일러가 Arduino 소스를 HEX 실행 파일로 변환한다. 일반적인 최상위 보조 함수가 사용 위치보다 뒤에 정의된 경우 Arduino 방식으로 함수 선언을 준비한다. 사용자 원본 파일을 변경하지 않으며 클래스·템플릿·기본 인자가 있는 함수는 이 보완에서 제외한다.
3. 실행 버튼 및 새 사진의 자동 실행은 해당 HEX와 현재 배선을 별도 AVR 실행기와 실제 ngspice 회로 해석기에 전달한다. 수동 조작용 실제 편집 상태는 시험 중 변경하지 않는다.
4. 다이얼·조도·토양·거리 센서와 버튼 중 MCU에 연결된 입력에 시험값을 넣고 MCU 코드를 실제 실행한다. 아날로그 입력은 회로 해석 전압을, 초음파 입력은 실제 TRIG/ECHO 펄스 모델을 사용한다.
5. LED는 회로의 전류, 서보는 실제 GPIO 펄스 폭과 공급 전원, 펌프는 회로 해석 전압과 부하 전류, 부저는 출력 에지의 주파수, LCD는 실제 4비트 명령/데이터와 전원을 확인한다. 부저의 실제 신호 핀 2도 네이티브 출력 모델에 연결했다.
6. 출력이 없거나 시험한 입력에 유효한 반응이 없으면 실패를 표시하고 자동 완료로 처리하지 않는다. 작은 펄스 지터는 반응으로 판정하지 않는다. 시험이 통과하면 같은 코드로 편집기 보드를 실행한다.
7. **조작·동작 검사**를 펼치면 입력 슬라이더·버튼·키보드 조작, 서보 실측값, 검사 상세와 결과 저장을 제공한다. 방향키는 첫 센서, Space는 첫 버튼이다. 코드 입력 중에는 키를 가로채지 않고 키를 놓거나 창을 벗어나면 버튼을 해제한다.
8. 검사 기록은 보드의 `evSimulationVerification` 속성에 저장해 기존 브라우저 초안·프로젝트 내보내기·작업공간 저장 경로를 따른다. 코드·배선 변경 시 이전 통과 표시를 사용하지 않고 다시 검사한다. 검사 기록을 임의로 수정한 파일을 실물 검증으로 취급하지 않는다.

## 코드 출력에 연결된 구조

- 실행 중 서보 신호 핀의 상승·하강 에지를 MCU 시간으로 측정한다. 실제 회로 해석에서 V+/GND가 유효하고 펄스가 도착할 때만 각도를 갱신한다. 신호가 없거나 전원이 끊기면 이전 각도를 유지하고 비활성 상태를 표시한다.
- 3D 서보 축은 그 각도를 읽는다. 사진 구조물에서는 기존 장착 관계와 좌우·상부·발목 역할을 이용해 관련 구동부·다리·발판을 움직인다. 배선 양 끝은 변환된 실제 핀을 계속 따라간다.
- 관절 축과 연결 계층은 **새 설계의 기구 가정**이다. 지면 접촉·균형·실제 보행 이동을 계산하는 물리 엔진은 아니다. 구조물은 실행을 정지하면 편집 기준 자세로 표시한다. 정지 후 구조물을 움직일 때 실행 자세가 설계 좌표에 섞이지 않는다.
- 급수는 기존의 실제 센서 전압 → MCU → MOSFET/펌프 전류 → 물 이동 → 토양 센서 되먹임을 사용한다. 별도 정해진 타이머로 펌프 동작을 꾸미지 않는다.

## 검사 범위

기본 입력·출력 시험은 자연어로 적힌 모든 인수 조건을 완전히 판정하는 기능이 아니다. 입력별 기본값/최소/최대, 거리 100cm 중간값 등 제한된 조건에서 동작을 확인한다. 입력이 있는 각 시나리오는 약 320ms, 입력 없는 출력은 약 1200ms를 실행한다. 긴 초기화·특수 순서·복잡한 조작은 이 기본 시험의 범위를 넘어설 수 있으며 실패 기록의 시나리오와 시간을 확인해야 한다.

UNO 이외의 보드와 측정 모델이 없는 출력은 `unsupported`로 구분한다. 기존 Raspberry Pi/모터 실드의 별도 운동 미리보기를 이번 MCU 기반 관절 실행과 같은 검증으로 표시하지 않는다. 임의의 모든 사진에서 완성된 물리 시뮬레이션을 보장하지 않는다.

## 파일과 증거

- 공통 입력·연결: `simulation/functional/circuit.ts`
- 코드·회로 기본 시험: `simulation/functional/FunctionalProbe.ts`
- 실행 전 검사·저장: `components/circuitiny/functionalVerification.ts`
- 사용자 조작: `components/circuitiny/FunctionalControls.tsx`
- 서보 측정·축 모델·기구 연결: `FunctionalRuntime.tsx`, `ServoBody.tsx`, `runtimeStructure.ts`
- 새 설계 보완: `backend/design/runtime_repairs.py`
- 실제 실행/표시 좌표 결과: `outputs/complete-runtime/actual-verification.json`
- 회귀 검사·빌드·타입 비교·패치 재현·서버 상태: 같은 출력 폴더의 로그와 JSON.

실제 저장된 4서보 로봇 코드를 사용해 거리 변경에 따른 구동/정지, 발판 좌표 변화, 조립·분해 상태의 배선 끝점 84개를 확인했다. 별도 조광·서보·급수·LCD·부저 코드를 컴파일/실행해 지원 출력도 검사한다. 새 유료 AI 호출은 하지 않는다. 브라우저 조작과 실물 검증은 별도로 구분한다.

최종 검사: 프런트엔드 **124개**, 백엔드·격리 컴파일 **54개** 통과. 잘못된 ADC 연결과 서보 전원 단선은 실패로 검출했고 실제 입력/출력 6종 실행 시험은 통과했다. TypeScript 전체 기존 오류 359개에 새 오류는 0개다. Vite 빌드와 upstream부터 29개 패치 재현도 통과했다. 실제 브라우저 조작 확인은 CUA의 `timeoutMs` 연결 오류로 완료하지 못했다.
