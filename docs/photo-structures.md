# 사진에서 구조물 오브젝트 생성

사진 분석은 전자 부품 목록과 별도로 `photo_structure`를 반환한다. 차체 판,
프레임, 바퀴, 지지대, 외장 케이스 등을 상자·원통으로 분해하고 사진의 색과
상대 배치를 근사한다. 형상에 근거가 없으면 `UNKNOWN`, `geometry=null`로
보존하고 관측 오브젝트를 생성하지 않는다. 그 위에 별도의 **전체 구조 설계**
단계를 적용한다. 2륜 로봇의 반대쪽 바퀴·뒤쪽 지지대·프레임·보조 바퀴는
`evDesignedStructure`로 생성하며 사진 근거로 취급하지 않는다.

- `backend/design/photo_structure.py`: 구조 스키마, 근거 이미지 검증,
  상대 좌표 → 편집기/운동 좌표 변환.
- `backend/design/inventory.py`: 새 사진·영상의 기존 Sol 분석 호출에서 구조도
  함께 받는다. 잘못된 구조 응답은 제외하며 기존 부품 분석 결과는 보존한다.
- `POST /api/projects/{project}/inventory/{plan}/photo-structure`: 과거 분석에
  구조가 없을 때 한 번 생성한다. `expected_revision`과 원본 그래프 해시를
  확인하고, 원본 분석을 수정하지 않는 별도 캐시에 저장한다. 모델 호출은
  프로젝트별 잠금으로 중복을 막는다. 빈 구조 결과도 캐시한다.
- `frontend/photo-structure.js`: 과거 프로젝트의 편집기를 열 때 누락된 구조를
  생성하고, 편집한 오브젝트를 운동 미리보기의 동일한 위치·크기·회전으로 변환한다.
- `withPhotoStructures`: 저장된 초안에는 새 구조만 추가한다. 기존 부품/배선/
  코드는 보존하며, 적용 후 사용자가 지운 구조는 다시 만들지 않는다.

구조물은 우선 독립 오브젝트로 생성하며, 지원하는 로봇 프로젝트는 내부 부품
배치와 배선 계산을 거쳐 조립 상태로 표시한다(`assembly-layout.md`). 오른쪽
`사진 구조물` 목록에서 선택하고 이동·크기·색상·회전을 편집한다. 근거와 가정은
선택 패널의 `사진 근거`에 접어 둔다. 구조물은 핀이 없는 `ev-structure`이고,
배선 검증·보드 전환·프로젝트 파일과 같은 수명 주기를 따른다.

운동 미리보기는 편집기에서 전달한 구조를 사용한다. 사진 구조가 있는 경우
같은 전체 구조 설계를 전달한다. 저장된 구조가 없는 단독 운동 화면도 동일한
보완 모듈을 사용한다. 실제 운동 계산의 바퀴 간격과
속도는 기존의 별도 가상 모델이며, 사진 형상이나 코드의 실측 결과가 아니다.
운동 화면의 구조 편집은 기존 구조 저장소에, 편집기의 구조 편집은 편집기
초안/프로젝트에 저장된다. 두 화면의 편집을 실시간으로 상호 동기화하지 않는다.

## 치수와 정확도

절대 치수는 `UNKNOWN`이다. 화면에서는 상대 길이 1을 **220 mm로 가정**한다.
이는 제작 치수가 아니며 사용자에게 명시한다. 원근, 두께, 깊이, 가려진 면,
비틀린 부재는 단일 사진으로 확정할 수 없다. `confidence`는 low/medium/high의
모델 판단이며 측정된 정확도나 확률이 아니다. 삼각형 메시 복원, 기계 강도,
간섭 검사와 실제 물리 시뮬레이션은 이 기능의 범위에 포함되지 않는다.

API 캐시는 `planner/{project}/{plan}-structure.json` 아래에 저장되며 프로젝트
삭제 시 원본 분석과 함께 제거된다. 서버 키나 원본 API 응답 본문은 저장하지 않는다.
