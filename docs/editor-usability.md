# 단계 안내와 시뮬레이터 편집 개선

2026-10-28 구현·검증.

## 사용법

1. 사진 분석 화면은 업로드 전부터 네 단계를 왼쪽에 표시한다. 진행 패널을 접으면 번호만 남으며 좁은 화면은 접힌 상태로 시작한다.
2. 시뮬레이터는 왼쪽의 **회로 확인 → 실행하기 → 결과 확인** 순서를 따른다. 단계 패널을 접으면 회로 공간이 더 넓어진다.
3. 2D·3D 공통 **＋ 부품 추가**로 부품을 고른다. 한국어 이름·설명·분류를 표시하며 한국어·영문·모델명으로 검색한다. 전기적 핀 이름과 부품 ID는 바꾸지 않는다.
4. 정지 상태에서 배선을 클릭하면 해당 배선의 양 끝 조작점만 표시한다. **파란 시작점 / 주황 끝점**을 새 핀으로 끌어 놓으면 실제 연결이 변경된다. 다른 곳을 선택하면 조작점이 숨겨진다. 2D와 3D는 같은 배선 데이터를 사용한다.
5. 연결할 핀이 없거나 이미 차지한 빵판 구멍, 중복 연결, 직접적인 보드 전원–GND 단락이면 연결을 유지하고 이유를 표시한다. Escape로 취소할 수 있다. 실행 중에는 배선을 편집하지 않는다.
6. **되돌리기 / 다시 적용**으로 끝점 변경을 취소·복구한다. 기존 배선 ID·색상·경유점은 보존한다.
7. **2D 위에서 보기**는 같은 회로를 정사영으로 수직 위에서 표시하고, **3D 입체 보기**는 입체 화면으로 전환한다. 정사영은 거리에 따라 물체가 작아지지 않는 표시 방식이다. 두 화면은 같은 부품·배선·코드·실행 상태를 사용한다.
8. **화면 이동 잠금**은 카메라의 이동·회전·확대/축소를 막고 부품과 배선 편집은 유지한다. 다시 누르면 잠금이 풀린다. 보기 전환과 가이드의 위치 확대는 잠금 중에도 직접 실행할 수 있다. 카메라의 관성은 꺼져 있다.
9. 일부 3D 기능이 필요에 맞지 않으면 **보기·도구 → 기존 2D 편집기 열기**를 사용한다. 2D 원본 편집기는 유지되며, 다시 위에서 보기 또는 입체 보기를 선택해 돌아올 수 있다.
10. 구조물·개발보드·빵판·일반 부품은 기본으로 고정한다. 오브젝트를 선택한 뒤 오른쪽 위 작은 정보 카드의 **이동 활성화**를 켜면 그 오브젝트만 드래그할 수 있다. **이동 완료** 또는 다른 선택으로 다시 고정한다. 빵판을 이동하면 꽂힌 부품도 함께 이동하고 실행 취소할 수 있다. 카메라 이동 잠금과는 별개다. [이동 조작 상세](object-movement.md).

## 구현

- `frontend/refined.css`: 분석 화면의 데스크톱 단계 안내.
- Velxio `EditorPage.tsx`, `EmbeddedWorkbench.css`: 접을 수 있는 왼쪽 진행 패널, 공통 부품 추가.
- `componentKorean.json`, `componentKorean.ts`, `useWorkbenchTranslation.ts`: 작업 화면에 한정한 한국어 표시. 설치 카탈로그의 모든 부품과 별도로 삽입되는 계측기 이름을 포함한다.
- `searchMatch.ts`: 한글을 제거하지 않는 유니코드 검색 정규화. 기존 영문·다국어 검색도 유지한다.
- `wireReconnect.ts`: 핀 위치 확인, 연결 검사, 끝점 변경과 실행 취소를 공통으로 처리한다. 드래그 미리보기는 회로 데이터를 바꾸지 않으며 놓을 때만 저장한다.
- `WireEndpointHandles.tsx`, `EndpointHandle.tsx`: 각각 2D·3D 마우스 드래그. 3D 드래그 중에는 카메라 조작을 잠시 막는다.
- `Viewer3D.tsx`: OrbitControls의 `enableDamping=false`, 자동 회전 비활성화.

## 검증

- 관련 회귀 테스트 **356개 / 18파일 통과**. AVR 시간·LED 밝기 전달, 빵판 연결, 2D/3D 공유 데이터, 배선 변경·되돌리기, 한국어·영문 검색 포함.
- Vite 제작 빌드 성공. 전체 TypeScript 검사는 기존 외부 소스의 진단 때문에 실패한다. 행 번호와 union 타입 표시 순서 차이를 정규화해 기존 기록과 비교했으며 새 진단은 없다.
- 검증용 독립 프로젝트에서 실제 마우스로 2D·3D 배선 끝을 `BB1.5t.a → BB1.6t.a`로 변경, 되돌리기와 3D 빈 공간 드롭 시 원래 연결 유지 확인.
- 한국어 `온도` 검색이 세 부품으로 좁혀지고 DHT22 추가가 실제 3D 회로에 반영되는 것을 확인.
- 마우스 해제 뒤 두 3D 화면은 **변경 픽셀 0개**. 정지 상태에서 측정했다.
- 왼쪽 진행 패널 접기·펼치기와 코드 함께 보기를 확인했다.
- 재설치용 패치는 고정 upstream에서 적용 검사 후 현재 소스와 바이트 단위로 대조한다.

증거: `outputs/editor-usability/verification.json`, 테스트·빌드 기록과 화면 캡처.

검증은 소프트웨어 편집 동작을 대상으로 한다. 부품 추가가 해당 보드의 서버 컴파일 지원 확대나 실물 작동 검증을 의미하지 않는다. 원본 사진의 Circuit Graph와 KiCad 파일은 수정하지 않았다.


## 업로드 전 단계 패널·끝 노드 직접 드래그 보완

- 사진 분석의 단계 안내를 프로젝트 영역 밖으로 옮겨 사진 업로드 전부터 보이게 했다. 접기·펼치기와 단계 이동도 지원한다. 최초 입력 전에는 2~4단계를 비활성화한다.
- 2D·3D 모두 모든 점퍼 배선 끝에 원을 표시한다. 선택 클릭 없이 바로 드래그한다. 경유점 편집은 기존처럼 배선을 선택해서 사용한다.
- 선택되지 않은 노드의 설명은 마우스를 올렸을 때만 보인다. 실행 중 또는 새 배선을 연결하는 모드에서는 기존 끝점 핸들을 숨긴다.
- 실제 브라우저에서 선택 도구 패널이 없는 상태로 3D·2D 각각 `BB1.5t.a → BB1.6t.a` 이동을 확인했다. 빈 공간 드롭 유지, 2D 수정의 3D 반영, 실행 취소도 확인했다.
- 관련 테스트 **75개 / 5파일 통과**, Vite 빌드 성공, 기존 기록 대비 새 TypeScript 진단 없음. 전체 타입 검사는 기존 upstream 진단이 남아 있다.
- 초기 업로드 화면은 동일한 프런트엔드 파일을 사용하는 임시 빈 프로젝트 서버로 확인했다. 운영 프로젝트를 삭제·초기화하지 않았다. 이미 프로젝트가 있는 실제 분석 화면에서도 단계 이동·접기·펼치기를 확인했다.
- 기록: `outputs/input-sidebar/`, `outputs/direct-endpoints/`.


## 3D 카메라 마우스 조작

왼쪽 드래그는 화면 이동, 오른쪽 드래그는 회전, 가운데 버튼과 휠은 확대/축소다. 3D에서 오른쪽 조작 중에는 배선 끝점 드래그나 센서·스위치 입력을 시작하지 않는다. 2D 편집과 3D의 왼쪽 부품 선택·배선 끝점 이동은 유지한다. 카메라 관성은 계속 꺼져 있다.

Three.js 실제 OrbitControls를 사용한 테스트에서 양 버튼의 이동/회전을 확인했고, 브라우저에서 왼쪽 화면 이동을 확인했다. 브라우저에서 오른쪽 드래그는 직접 검사하지 않았다. 관련 회귀 26개 통과, Vite 빌드 성공. 기존 upstream TypeScript 진단 외 새 진단 없음. `outputs/mouse-controls/`에 기록했다.
# 빵판 연결 미리보기

시뮬레이션을 정지한 상태에서 기존 배선의 끝점을 끌어 빵판 구멍 위에 올리면, 2D와 3D에서 해당 구멍이 속한 빵판 내부 연결선 하나와 그 줄에 직접 꽂힌 부품을 주황색으로 강조합니다. 선을 놓기 전까지 실제 회로는 바뀌지 않습니다. 구멍을 벗어나거나 취소하면 표시가 사라지고, 연결할 수 없는 구멍은 이유를 표시합니다. 점퍼선으로 이어진 다른 줄의 부품과 외부 배선은 강조하지 않습니다. 부품 강조는 연결 위치를 알려 주는 표시이며 전원이 켜졌다는 뜻은 아닙니다.

빵판 가운데 홈 양쪽은 별도이며, 전원 레일은 시뮬레이터에서 각 레일 전체가 이어진 것으로 모델링합니다. 실제 빵판의 레일이 중간에서 분리되어 있는지는 별도로 확인하세요. 새 배선을 클릭으로 만드는 모드가 아니라 기존 배선 끝점을 끄는 동작에 적용됩니다.
