# GPT 부품별 확대·재검토 스킬

사진·영상 입력에서 선택한 Sol/Astra에 `embedded-system-inspection` 스킬을 기본 적용한다. 서비스 소유 스킬은 `data/agent-skills/embedded-system-inspection/SKILL.md`에 있다. OpenAI의 공식 전자회로 검사 스킬이라고 주장하지 않는다. [OpenAI Docs의 Agent Skills 형식과 로컬 shell 연결](https://developers.openai.com/api/docs/guides/tools-skills)을 사용하는 프로젝트 전용 스킬이다.

## 실행 흐름

기본 경로는 마지막 결과만 JSON으로 받는다.

1. 사진·영상에서 부품별 ID·수량·표식을 자유 문장으로 기록한다. 보드 참고 프로파일은 제공하지 않는다.
2. 원본 전체와 겹치는 분할 확대에서 후보 ID별로 다시 검토하고 누락·중복·미확인 영역을 자유 메모로 정리한다.
3. 이 관측 메모를 고정한 뒤에만 보드·부품 참고자료를 제공해 기능·추가 부품·새 회로·코드·구조를 자유롭게 설계한다.
4. 마지막 통합 JSON 하나로 관측 목록·설계·검토 ID·미검토 영역을 받는다. 최종 관측 ID는 재검토 메모에도 있어야 한다. 기존 회로·핀·참조 검사로 편집기에 전달한다.
5. 최종 부품별 잘라보기 이미지는 화면 확인용으로 만들며 별도 모델 재검토 호출로 집계하지 않는다. 중간 메모·원본 확대·최종 구조화 검증을 구분한다.

이전 후보별 JSON 재검토 경로는 `ResponsesProvider(photo_pipeline='staged_json')`의 명시적 내부 비교 경로로 유지한다. 기본 사진·영상·SaaS 경로는 `final_json`이다. 중간 작업 메모는 사용자 입력과 마찬가지로 신뢰하지 않는 텍스트이며 명령으로 실행하지 않고 UI에서 이스케이프해서 표시한다.

## 실제 스킬 바인딩

Responses 요청에 `shell` 도구와 `environment.type=local`, `skills=[{name, description, path}]`를 포함한다. 실행 파일은 가상 경로 `/workspace/skills/embedded-system-inspection`에 노출된다. 모델은 `cat .../SKILL.md`와 선언한 `python3 .../scripts/crop.py --asset ... --part ... --box ... --original` 명령만 요청할 수 있다.

서버는 명령을 OS 셸에 전달하지 않고, 허용된 스킬 읽기와 등록 입력의 원본 확대 함수로 해석한다. 따라서 임의 파일 읽기·쓰기·네트워크·프로세스 실행은 제공하지 않는다. `shell_call_output`과 실제 확대 이미지가 후속 모델 요청에 전달된다. 서버가 필수 부품 확대를 직접 수행하므로 모델이 도구 호출을 생략하더라도 필수 확대 검토는 생략되지 않는다. 스킬 지침은 서버도 읽어 요청에 적용하며 해시를 저장한다.

`shell_call_output.max_output_length`는 해당 `shell_call.action.max_output_length`와 정확히 일치시킨다. 요청에 없으면 응답에도 새 값을 넣지 않는다. 실제 텍스트는 이 요청값과 서버 상한 12,000자 중 작은 범위로 제한한다. 요청값을 무시하고 응답에 12,000을 고정하면 Astra가 2,000을 요청한 확대 도구의 후속 요청에서 HTTP 400이 발생하는 것을 실제 사진 분석에서 확인했다(2026-11-12). 관련 기록은 `outputs/astra-reanalysis/`에 보존한다.

추가 도구 확대는 4개, 전체 모델 HTTP 호출은 설계 단계를 합쳐 16회, 전체 호출 시작 시각 기준 720초다. 시간/호출 한도, 모델 오류, ID 누락·충돌은 자동 재시도하지 않는다. 모델 응답 오류로 분석이 중단되어도 원본은 보존하고 진행 보고서를 작업에 남긴다.

초기 목록화의 선택적 도구 왕복은 한 차례로 제한한다. 스킬 지침은 이미 요청에 포함돼 있어 재읽기를 지시하지 않으며, 필요한 추가 영역은 한 도구 묶음으로 요청하도록 한다. 도구 응답 이후에는 `tool_choice=none`으로 첫 목록 JSON을 먼저 받는다. 원본 후보별 필수 확대·재검토는 이후 서버 단계에서 수행한다. Astra를 선택해도 모델은 유지하되 관측·재검토 메모와 최종 JSON 정리는 `medium`, 기능·회로 추론 메모는 `high` 추론 강도로 요청한다. 실제 지연·인식 정확도의 개선 수치는 별도 유료 검증이 필요하다. 서버가 이미 원본 확대와 전체 스킬 지침을 전달하는 부품 재검토·누락 검사에서는 `tool_choice=none`으로 불필요한 재읽기를 막는다. 필수 확대·부품별 모델 재검토는 그대로 실행하며 전체 호출 한도를 늘리지 않는다.

## 화면과 저장

분석 패널에 6단계와 **부품별 확대·재검토** 토글을 표시한다. 후보별 확대 이미지·읽힌 표식·검토 상태·한계를 볼 수 있다. 결과의 `component_inspection`에 스킬 바인딩·해시·원본 SHA·확대 영역·검토 ID·누락 추가·중복 제거·미검토 영역·호출 수를 기록한다.

확대 이미지는 새 공개 파일로 배포하지 않고 같은 프로젝트 권한을 검사하는 `GET /api/projects/{project}/planner/{plan}/inspection/{crop}`로 제공한다. 원본과 확대 처리 해시가 다르면 재사용하지 않는다. SaaS의 작업공간 경계도 유지한다. 기존 분석·이미지·편집 초안은 변경하지 않는다.

## 검증 범위

네이티브 Skills 요청과 도구 루프는 MockTransport로 검사한다. 원본 자르기·확대·재현 해시와 API 이미지 반환은 실제 Pillow로 실행한다. 모델 분석 품질·실제 유료 API 호출·실물 작동 검증은 별도다. 검증 증거는 `outputs/component-inspection/`에 저장한다.

최종 결과: 회귀 검사 226개, 최종 기능 검사 17개 통과(회귀 범위에 포함). 네이티브 스킬 요청·도구 응답·확대 이미지 전달은 MockTransport로 검증했다. 원본 자르기·확대와 독립 스크립트는 실제 실행했다. 전체 프런트엔드 로컬/SaaS 사진·영상 업로드 및 확대 결과 토글 검사, 페이지 번들 검사 통과. 실제 8897·8766·SaaS 8770의 스킬 활성 상태와 워크플로우 v5 확인. 서버·작업자 재시작 전후 기존 입력·분석 파일 146개 동일, 유료 AI 호출 0회. 직접 브라우저 조작·실물 검증은 진행하지 않았다.

## 오류 진단 보완

모델 응답 오류를 JSON 문법 해석 실패와 필수 필드·자료형·값 범위 검증 실패로 나눠 기록한다. `output_phase`, 필드 경로, 오류 종류, 응답 해시·길이와 안전한 응답 ID를 남긴다. 입력 값·모델 본문·사용자 지정 키 이름·API 키는 진단에 복사하지 않는다. 시간 초과는 요청 수·도구 왕복 수·경과 시간을 기록한다. 과거에 상세 정보를 저장하지 않은 실패의 정확한 필드 원인을 소급 복원할 수는 없다.

## 최종 JSON 기본 경로 검증（2026-11-12）

현재 기본 경로에 대한 관련 Python 검사 137개와 명령어 보기·복사/편집기 주소 JavaScript 검사 4개가 통과했다. Sol·Astra, 사진·다중 영상 프레임, 선택적 스킬 도구, SaaS 작업자, 데이터시트·편집기 배선/코드, 확대 이미지 권한을 모의 API로 검사했다. 중간 자연어를 JSON으로 읽지 않고 마지막 요청 1개에만 strict JSON 형식을 지정하는 것을 확인했다. 최종 필드 누락과 관측 메모에 없는 부품 ID는 전달하지 않았다. 유료 모델 재분석과 실제 인식 품질·지연 측정은 하지 않았다. 기존 후보별 JSON 방식의 검사는 명시적 비교 경로에 대한 회귀 기록이다.
