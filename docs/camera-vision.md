# 실사 사진·영상 VLM 프로토타입 0.3

2026-10-20. 기존 설계 예제와 별개로, **실제 카메라 촬영 사진을 모델에 입력하는 경로**를 구현했다.

**2026-10-21 개선:** 현재 기본 분석기는 전체 탐색 → 부품별 확대 재검토 → OCR 위치 대조를 사용하며 AI 문장으로 배선을 생성하지 않는다. 아래 0.3 단일 호출 시험은 과거 기록이다. [개선 구조와 검증](staged-photo-analysis.md)을 참고한다.

## 모델 선택

사용자가 요청한 VLA는 Vision-Language-Action, 즉 영상·언어를 로봇 행동으로 연결하는 모델이다. [OpenVLA 공식 구현](https://github.com/openvla/openvla)은 로봇의 동작 값을 예측한다. 회로 사진에서 부품·텍스트·배선 후보를 얻는 이번 단계에는 VLM(Vision-Language Model)을 연결했다. **VLA를 실행했다고 부르지 않는다.**

- 모델: [Qwen3-VL-2B-Instruct](https://huggingface.co/Qwen/Qwen3-VL-2B-Instruct).
- 배포: [ggml-org GGUF](https://huggingface.co/ggml-org/Qwen3-VL-2B-Instruct-GGUF), revision `ea6a11058182570be6436b9a2e4ee7f7b49f908d`.
- 런타임: [llama.cpp](https://github.com/ggml-org/llama.cpp), b11669 CPU, 4 threads, context 4096, 이미지 1024~1280 tokens.
- 모델+영상 인코더 약 2.3 GB 다운로드. GPU/외부 API 없이 localhost에서 실행한다. 사진을 외부 서비스에 보내지 않는다.

## 사용

현재 서버가 실행 중이다: http://127.0.0.1:8766.

1. **실제 촬영 사진 분석**을 누르면 공개 실사 사진을 열고 모델을 실행한다. 부품이나 정답 연결을 미리 넣지 않는다.
2. **＋ 사진**으로 촬영 사진을 올리면 자동으로 VLM 분석을 시작한다. 모바일에서는 지원 브라우저의 후면 카메라 입력을 요청한다.
3. **＋ 영상**은 주요 프레임 최대 6개를 고르고 차례로 VLM에 넣는다. 실제 동영상 전체를 한 번에 이해하거나 동일 부품을 프레임 사이에서 추적하는 방식은 아니다.
4. 모델의 부품 영역을 원본 사진에 표시하고 같은 Graph에서 회로 초안을 만든다.
5. 모델의 요약·추가 확인 질문을 읽는다. **오인식 후보 제외·단자 라벨 보완**에서 잘못된 부품을 제외하거나 읽을 수 있는 단자를 추가한다. 이전 수정 이력은 보존한다.
6. 배선의 두 끝점, 값, 모델, 실제 핀을 확인한 뒤 기존 카탈로그·KiCad 경로로 진행한다. 이번 실사 예제는 연결이 불확실하여 생성 차단 상태다.

재실행은 터미널 두 개에서:

```bash
cd /home/snowflower/CVR_LAB/PCB/embedded_vision
bash run_vlm.sh
```

```bash
cd /home/snowflower/CVR_LAB/PCB/embedded_vision
bash run.sh
```

다른 Linux x86_64 환경에 모델을 준비하려면 Python 3.12 가상환경 설치 후 `.venv/bin/python scripts/setup_vlm.py`를 실행한다. 버전·SHA256을 고정하고 프로젝트 내부에만 저장한다. 생성하는 로컬 API 인증키는 `.runtime/vlm/api-key`에 권한 0600으로 저장하며 웹에 노출하지 않는다.

## 실제 시험 결과

- 입력: Thctamm의 [Arduino Uno with breadboard](https://commons.wikimedia.org/wiki/File:Arduino_Uno_with_breadboard.jpg), 실제 카메라 사진, 1440×2560. CC BY-SA 3.0. 출처는 화면과 `data/photos/ATTRIBUTION.md`에 표시한다.
- 모델 입력: 비율을 유지한 567×1008 JPEG. 파일명·이미지 설명·회로 정답은 모델 프롬프트에 전달하지 않았다.
- 최초 시험: 답변 길이 제한으로 실패. 부분 JSON을 그래프에 반영하지 않았다.
- 부품 수·문장 길이 제한 후: **88.8초**, 986 출력 tokens, 6개 부품 후보.
- Arduino/브레드보드 후보는 찾았으나 저항의 위치·표식과 연결에서 오인식이 있었다. 이는 정확도 검증 통과가 아니다.
- 존재하지 않는 단자에 대한 배선 제안 5개를 버렸다. 남은 3개도 모델의 말 외에 끝점 근거가 없어 **UNKNOWN**으로 보존한다.
- 저항 값과 실제 핀 번호는 UNKNOWN. 자동 CONFIRMED 0개. KiCad 생성 차단.
- 브라우저에서 실사 예제 생성·백그라운드 분석·Graph 갱신·원본 사진과 모델 후보 표시를 확인했다.
- 실제 사용자 영상에 대한 인식 정확도는 미측정이다. 기존 프레임 추출 테스트와 다중 자산 처리 구조를 재사용한다.

검증 기록은 `.runtime/daf2f303714c436f85cdb05f2dae404d-vision.json`, 원시 모델 응답은 같은 프로젝트의 `-vlm-<job>.json`, 수정 버전은 SQLite에 남아 있다. 초기 원시 결과를 숨기거나 정답으로 바꾸지 않았다.

자동 검증: 전체 61개 테스트 통과 후 다중 프레임/동시 수정 2개를 추가했고, 실사 테스트 10개를 다시 통과했다. 총 63개 테스트 범위. 1개 경고는 기존 TestClient의 httpx 사용 중단 예고다.

## 검증 규칙

- JSON schema로 모델 출력을 제한하고 다시 Pydantic 검증한다. 범위를 벗어난 좌표·중복 ID·없는 단자 참조는 거절한다.
- 부품은 INFERRED, 값/패키지 핀은 UNKNOWN. 모델이 “양 끝점이 보인다”고 주장해도 독립 근거가 없으므로 배선은 UNKNOWN이다.
- 모델 점수를 보정된 신뢰도로 표시하지 않는다.
- 분석 중 사용자가 그래프를 수정하면 오래된 결과로 덮어쓰지 않는다.
- 모델이 꺼지거나 응답이 잘리면 오류를 표시한다. 합성 회로나 이전 결과로 대체하지 않는다.
- 반복 분석은 새로운 후보를 추가한다. 중복 후보는 사용자가 제외해야 한다. 서로 다른 프레임의 부품을 자동 병합하지 않는다.
