# 분해 보기와 회로·배선 보기의 핀 연결 표시

기존 일반 기능 설계에는 센서와 서보의 실제 네이티브 핀이 있었지만, 장착 속성이 있다는 이유만으로 전용 로봇 기구 배선 계산을 모든 연결에 강제했다. 이 계산기는 일부 보드·모터 모델만 지원하므로 예제의 21개 배선 모두 경로 실패로 처리되고 `Wires3D`에서 숨겨졌다. 이전 분해 보기 검증은 끝점 21쌍의 존재를 확인했으며, 실제 케이블 렌더링까지 확인하지 못했다.

이번 변경은 다음을 분리한다.

- 기구 계산에 성공한 연결: 기존 경로를 표시하고 실제 네이티브 핀에 끝점을 고정한다.
- 기구 계산기가 지원하지 않는 부품: 기존 핀 ID·현재 위치·사용자 경유점을 사용하여 표시용 배선을 만든다. 부품 위로 지나도록 높이를 분리한다. 전기적 연결은 바꾸지 않는다.
- 지원 모델에서 실제 기구 경로 계산이 실패한 연결: 연결을 숨기지 않고 주황색 점선 보조 표시로 보여준다. `routeBlocked`와 실패 이유는 유지한다.
- 아직 핀 위치를 읽지 못한 연결: 핀을 지어내지 않는다. `배선 N/M` 목록에 준비 중으로 표시하고 네이티브 핀이 준비되면 갱신한다.

분해 보기의 회로 부품과 전선에는 같은 위치 이동을 적용한다. 회로·배선 보기에서도 화면 크기에 따른 선 두께를 보강하며, 선택한 선에는 두 핀의 이름을 표시한다. 카메라 맞춤에는 실제 표시 경로의 높이도 포함한다. 화면용 선 강조는 운동 미리보기 전달에서 제거하고 케이블 메시를 유지한다.

단일 사진에서 원본 전선의 굴곡을 복원했다고 주장하지 않는다. 표시 경로는 이미 설계된 회로의 실제 핀 연결을 보여주며, 기구 간섭이나 실물 제작 가능성이 검증된 것으로 취급하지 않는다.

## 검증

기존 로봇 예제에서 수정 전은 물리 경로 실패 21개·표시 경로 0개였다. 수정 후 `connectedWirePath`로 표시 경로 21/21개가 생성되고, 각 첫 점과 끝 점이 네이티브 핀의 위치와 일치한다. 입력·기존 회로·코드·분석은 보존하며 추가 AI 호출은 없다.

별도 서보 예제는 실제 Wokwi 핀을 등록한 뒤 React의 `Wires3D`를 렌더링해 케이블 메시 개수, 두 보기의 표시, 조립 보기에서 숨김, 연결 목록, 위치 이동을 검사한다. 이전처럼 연결 데이터 개수만 세지 않는다. 브라우저 자동화는 `getTab`의 `timeoutMs` 오류로 실제 브라우저 클릭 검증을 수행하지 못했다.
