최초 인증 실패 시 화면에는 분석 실패가 표시되고 회로 생성 단계는 비활성화됐다. 구체적인 오류는 자동 분석의 ‘분석 단계·처리 방식’을 펼쳐 확인할 수 있었다.

별도 포트의 로컬 Qwen 모델로 전체 사진 단일 탐색을 추가로 시험했다. 기본 자동 설계 경로가 아니라 독립 진단이며 부품 확대 재검토나 시뮬레이션은 실행하지 않았다.

- 로봇: 보드, 바퀴, 전지, 모터 후보를 찾았지만 초음파 센서를 카메라로 오인하고 노트북을 부품에 포함했다.

이 사례들을 완전히 지원하려면 거리 센서·LCD, 로봇 모터와 회피 동작, 토양 센서·펌프 구동 회로 및 해당 보드 코드를 추가하고 실행 검증해야 한다. 사진만으로 동작이나 안전성을 확정하지 않는다.

## 후속 구현

기능 후보 선택 후 별도의 Arduino 회로·코드 편집기를 열 수 있도록 세 가지 새 시제품을 추가했다. 세 설계는 사진의 원래 핀이나 프로그램을 복원하지 않는다.

- 거리 표시: UNO, HC-SR04, LCD, LED와 빵판 배선. 가상 거리 10 cm와 34 cm에서 Arduino 시리얼 거리와 LED가 바뀌는 것을 브라우저에서 확인했다. 근접 기준 20 cm는 새 설계의 가정이다.
- 자동 급수 제어: UNO 코드가 가변 입력을 읽고 펌프 명령 LED를 제어한다. 입력 650에서 켜고 500에서 끄는 예제 기준을 둔다. 3D 편집기에서 입력을 0 → 1023 → 0으로 바꿔 시리얼 명령과 LED가 꺼짐 → 켜짐 → 꺼짐으로 바뀌는 것을 확인했다. 가변저항과 LED는 토양 센서와 펌프 명령을 대신하는 시뮬레이터 부품이며, 실제 펌프 구동 회로와 물 흐름을 시뮬레이션하지 않는다.
- 장애물 회피 로봇: UNO, HC-SR04, L293D, 좌우 모터와 전원 연결 및 코드를 만든다. 모터와 전원은 편집기에서 시각 부품이다. 별도 3D 운동 모델에서 가상 거리를 바꾸면 전진·후진·회전을 하고 센서 응답이 없으면 정지한다. 3D 모델은 편집한 코드를 실행한 결과가 아니다.

생성한 거리·급수 코드는 가상 MCU에서 입력별 출력 반응을 시험했다. 로봇 코드는 컴파일하고 모의 센서 입력으로 모터 명령 순서를 시험했다. 실제 전기 정격, 조립 및 원본과의 동등성은 검증하지 않았다.

## 사진 업로드 후 자동 실행

새 업로드는 가장 우선인 기능 후보가 지원 설계와 일치할 때 자동으로 새 회로를 준비하고, 같은 탭의 편집기로 이동해 기존 회로 검사·Arduino 코드 컴파일을 거쳐 실행한다. 지원하지 않는 후보는 다른 기능으로 바꾸지 않는다. 분석 화면으로 돌아오거나 기존 프로젝트를 열 때는 자동으로 다시 이동하지 않는다. 저장된 편집 초안을 복원한 경우 자동 실행하지 않는다.

공개 주차 사진을 실제 업로드 API와 모델로 분석해 거리 표시 회로가 자동 선택되는 것을 확인했다. 생성된 회로를 브라우저에서 자동 실행해 가상 보드가 동작하는 것을 확인하고 정지 후 재시작되지 않는 것도 확인했다. 자동 전환·복귀 방지 등은 프론트엔드 자동 테스트로 검증했다. 브라우저 파일 선택부터 같은 탭 자동 전환까지의 전체 경로는 테스트 브라우저의 파일 업로드 권한 제한으로 직접 검증하지 못했다.

자동 생성은 현재 제공된 설계의 범위에 한정된다. 급수 예제는 펌프를 LED로 대체하며, 로봇의 별도 가상 운동은 Arduino 코드나 모터 전기 모델의 실행이 아니다. 실물 작동이나 임의 사진에 대한 성공을 보장하지 않는다.
