# 편집기 / 분석기 서비스 분리

2026-11-12. 개발의 기본 도착점을 독립 편집기로 바꿨습니다.

| 구분 | 편집기 | 분석기 |
| --- | --- | --- |
| 소스 | `services/editor` | `services/analyzer` |
| 실행 | `bash services/editor/start.sh` | `bash services/analyzer/start.sh` |
| 주소 | `http://127.0.0.1:8768/` | `http://127.0.0.1:8766/` |
| Python | 해당 서비스 `.venv` / 18개 패키지 | 해당 서비스 `.venv` / 영상·OCR 포함 |
| 데이터 | `.runtime/editor` | 기존 `.runtime` |
| 환경변수 | `EMBEDDED_EDITOR_DATA` | `EMBEDDED_ANALYZER_DATA` |
| API 키 | 기본 편집·UNO 실행에 불필요 | 외부 AI 분석에 필요 |

`shared/backend`와 `shared/data`는 공용 회로·보드·부품 규칙입니다. 루트 `backend.*` import는 소유 디렉터리로 연결하는 호환 링크를 사용합니다. 따라서 소스와 실행 서비스는 분리했지만 공용 코드를 별도 패키지로 배포하는 단계는 아닙니다.

## 입력·출력 경계

편집기의 입력은 내장 보드 예제 또는 `.vlx` 프로젝트입니다. 보드·부품·배선·코드·구조물을 유지하고, 자체 프로젝트 저장소의 짧은 ID로 편집기를 엽니다. 사진 분석 API나 작업 큐를 시작하지 않습니다. 대용량 파일을 URL에 싣지 않습니다.

분석기는 이미지/영상에서 회로·구조·코드를 만들어 `.vlx`로 전달합니다. 편집기 미설치 시 `shared/data/simulator-catalog-snapshot.json`의 이름 목록을 참조합니다. 이는 핀·전압의 데이터시트 검증 자료가 아닙니다.

기존 분석 화면의 직접 편집기 열기와 브라우저 저장 키는 유지합니다. 기존 로봇 프로젝트의 분석 서버에 연결된 동작 미리보기는 분석기 API가 필요할 수 있습니다. 회로·코드·3D 편집과 UNO 컴파일·실행을 먼저 독립화한 범위입니다.

## 기존 설치의 이동

구버전 설치에 실제 `third_party/velxio`, `.tools/avr`, `.tools/npm` 디렉터리가 있고 새 위치가 없으면 편집기 설치기가 각각 `services/editor/vendor/velxio`, `services/editor/.tools/avr`, `services/editor/.tools/npm`으로 이동합니다. 이전 위치에는 호환 링크를 만듭니다. 두 위치에 실제 설치본이 모두 있으면 어느 쪽도 덮어쓰지 않습니다. 기존 `.venv`, 입력·키·분석 기록은 이동·삭제하지 않습니다.

새 독립 편집기 패치는 기존 설치에 충돌 없이 적용할 수 있을 때만 추가합니다. 사용자 변경과 충돌하면 설치를 멈추고 백업 후 재구성을 안내합니다. 전체 벤더 초기화는 하지 않습니다.

## 실행 방식

루트 `bash start.sh`는 편집기만 설치·실행합니다. `--service analyzer`는 Node·AVR·편집기를 설치하지 않습니다. `--service all`은 두 서비스를 각각의 Python 환경에서 실행하고 한 서버 종료가 다른 서버를 종료시키지 않습니다. 기본 설치는 SaaS API/worker를 자동 시작하지 않습니다.

별도 프로세스로 이미 실행 중인 서버는 설치기가 강제로 종료하지 않습니다. 변경된 코드 적용은 해당 서버 재시작이 필요합니다. 데이터 폴더 변경 시 키 설정 명령에도 같은 서비스별 데이터 환경변수를 지정하세요.
