# 단계별 인터페이스

2026-10-27. 기존 분석·회로 생성 기능을 5단계로 정리했다. 단계 이동은 화면만 변경하며, 분석이나 생성은 각 실행 버튼에서 수행한다.

| 단계 | 입력 | 처리 | 출력 |
|---|---|---|---|
| 1. 입력 확인 | 사진 1장 또는 영상 1개 | 저장된 이미지/주요 프레임 확인 | 파일 정보와 현재 분석 현황 |
| 2. 부품·문자 | 선택한 이미지 | 부품 탐색·확대 검토·OCR·핀 위치 검토 | 부품 후보, 문자 영역, 핀 위치 |
| 3. 배선 추정 | 선 조각과 실제 핀 위치 | 색상·방향·굵기·간격 비교, 대안 검토 | 경로 가설과 선택한 추론 연결 |
| 4. 회로 검증 | 부품·핀·연결·근거를 담은 Circuit Graph | 카탈로그·값·핀 매핑·연결 조건 확인 | 미해결 항목과 실제 검사 상태 |
| 5. 결과물 | 조건을 충족한 현재 회로 데이터 | KiCad·ERC·PCB·DRC·지원 회로 시뮬레이션 | 파일, 검사 결과, 파형, 코드·가이드 |

## 화면 변경

- 상단 5단계 탐색과 이전/다음 버튼. 새 프로젝트를 열면 입력 확인으로 돌아간다.
- 모든 단계에 입력·처리·출력 카드, 현재 리비전과 선택한 이미지 표시.
- 입력 단계는 원본 사진과 분석 현황, 부품 단계는 인식·핀 검토, 배선 단계는 가림 가설, 검증 단계는 회로·근거·미해결 항목을 보여준다.
- 결과물은 회로 데이터, KiCad/PCB, 파형, 코드/설명으로 나누고 실제 산출물 유무를 표시한다. 현재 리비전에 결과가 없으면 미생성/미계산 상태다.
- 후보가 존재한다고 완료 표시를 하지 않는다. 예: 부품 후보 4개, 경로 가설 30개, 핀 위치 0개, 연결 0개가 함께 표시된다.
- 미해결 조건이 있는 경우 생성·계산 버튼을 비활성화하고 검증 단계로 돌아가는 버튼을 제공한다. 기존 서버 검증도 유지한다.
- 예제는 상단 ‘예제 열기’로 모았다. 실사와 새 설계 예제를 구분한다.

## 구현

`frontend/workflow.js`는 서버가 반환한 Graph/readiness/EDA/simulation 데이터를 요약한다. `workflow.css`가 선택한 단계에 필요한 기존 패널을 표시한다. `integrated.js`가 단계 이동과 결과물 하위 화면을 연결한다. 백엔드 분석·추론 알고리즘과 회로 데이터는 변경하지 않았다.

## 검증

- 실사 프로젝트에서 5단계 이동, 입력·처리·출력 표시, 가림 가설 30개 및 대안 선택, 검증 항목, 카탈로그 진입, 결과물 하위 화면을 브라우저에서 확인.
- 실사 미검증 프로젝트의 전체 생성/회로 생성/시뮬레이션 버튼이 비활성화되는지 확인.
- 저장된 ESP32 예제의 ERC/DRC PASS와 실제 파형이 결과물 단계에서 열리는지 확인. 새 회로 생성이나 원본 수정은 수행하지 않음.
- 기존 프로젝트 전환 시 입력 단계로 복귀 확인.
- 이 변경은 UI 검증이며 배선 인식 정확도·실물 작동 검증이 아니다.
