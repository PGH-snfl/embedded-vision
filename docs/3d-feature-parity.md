# 2D / 3D 편집 기능 연동

2026-10-28. Circuitiny 기반 3D 편집기의 기능을 확장했다.

## 사용 순서

1. 기존 그래픽 편집기를 열고 **3D 편집**을 선택한다.
2. **＋ 부품 추가**에서 2D와 같은 전체 부품 목록을 사용한다.
3. 부품을 선택해 이동·회전·복사·삭제하거나 **상세 속성·핀 정보**를 연다.
4. **핀 연결**에서 3D 핀 또는 시작·도착 목록으로 연결한다. 연결 중 바닥을 누르면 경유점이 추가된다.
5. 배선을 클릭하거나 **보기·도구 → 배선 목록**에서 선택한다. 색 변경, 경유점 추가·이동·삭제, 분기점, 파형 측정을 사용할 수 있다.
6. **코드 함께 보기 → 시뮬레이션 실행**으로 실행한다. 3D 버튼·스위치·다이얼을 조작하거나 센서 패널을 연다.
7. **프로젝트 저장**으로 기존 `.vlx` 형식으로 저장한다. SaaS 작업공간 저장 흐름도 기존과 같다.

## 구현 내용

| 기능 | 3D 동작 |
|---|---|
| 부품·보드 추가 | 기존 전체 부품 선택 창 공유. 복수 보드 및 보드 없는 회로 표시 |
| 이동·회전 | 네이티브 좌표와 핀 위치 사용. 빵판 이동·회전 시 꽂힌 부품과 삽입 연결 유지 |
| 속성·핀·데이터시트 | 기존 상세 정보 창 재사용. 보드 핀 정보 창에서 시작한 연결도 3D 배선으로 전달 |
| 복사·붙여넣기·삭제 | 기존 프로젝트 상태와 명령 사용. 기존에 이력이 제공되는 명령은 같은 Undo/Redo 공유 |
| 키보드 | R, Ctrl/Cmd+C/V/Z, Shift+Z, Delete, Escape. 입력창·코드 타이핑은 가로채지 않음 |
| 배선 | 실제 네이티브 핀·연결·색·경로 공유. 경유점 드래그, 분기점, 삭제, 복원 |
| 빵판 연결 | 실제 구멍 좌표로 스냅·삽입 연결 갱신. 회전한 빵판에서도 같은 구멍 사용 |
| 버튼·스위치·일반 입력 | 원래 시뮬레이터 요소에 실제 이벤트 전달. 키패드·다이얼 등은 표시 면의 위치를 원본 제어에 전달 |
| 센서 | 기존 SensorControlPanel과 실시간 센서 등록부 재사용 |
| LCD·OLED 등 | 원본 시뮬레이터의 SVG/Canvas 출력을 3D 표면에 표시 |
| 파형 | 기존 GPIO/전기망 측정기를 사용. 임의 파형 생성 없음 |
| 코드·실행·출력 | 기존 편집기·컴파일러·AVR8js/ngspice·시리얼 창 공유 |
| 저장 | 기존 브라우저 저장·SaaS 초안 저장·`.vlx` 다운로드 유지 |

## 구조

2D / 3D → **동일한 native store·history·electrical engine**.

- `geometry.ts`: 원본 요소의 실제 핀과 SVG/Canvas 크기, 회전 중심을 읽는다. SVG보다 작은 인라인 요소 높이에 의해 LCD가 납작해지는 문제를 보정했다.
- `bridge.ts`: 모든 부품·보드와 실제 배선을 공통 3D 표현에 등록한다. 읽을 수 없는 핀은 생성하지 않는다.
- `actions.ts`: 이동·회전·속성·복사·배선·분기점·측정을 원래 프로젝트 명령으로 처리한다.
- `Wires3D.tsx`: 실제 배선 경로와 경유점, 연결 중 미리보기.
- `NativeFace.tsx`, `nativeInteraction.ts`: 실제 표시 출력의 텍스처와 원본 입력 요소로의 이벤트 전달. 독립된 가짜 시뮬레이터를 만들지 않는다.
- `sharedTools.ts`: 공통 부품 선택 창·보드 정보·커스텀 부품 코드 편집을 연결한다. 3D가 열려 있으면 보드 정보 창의 핀 선택을 3D가 처리하고, 2D에서는 기존 동작을 유지한다. 보드 옵션 창은 숨겨진 2D 영역 밖으로 표시해 키보드와 마우스로 조작할 수 있다.
- `breadboardSnap.ts`: 기존 2D 스냅 경로도 회전한 빵판의 구멍을 계산하도록 확장했다.

실행 중 배선·부품 편집은 잠근다. 버튼/스위치/센서 입력은 계속 가능하다. 버튼과 제어면은 창 포커스를 잃거나 포인터를 놓으면 해제한다.

## 검증

- 관련 프런트엔드 **137개 테스트 / 7파일 통과**. 이번 추가 테스트 15개는 일반 부품 핀, 불명 핀 미생성, 복수 보드, 보드 없는 회로, 회전 좌표 일치, 빵판과 부품의 회전·복원, 속성 복사, 배선 색·경유점·Undo, 실제 버튼 이벤트, 원본 제어면 이벤트, SVG 크기, 분기점 복원, 실제 측정 채널, 정보 창 핀 선택 전달을 검증한다.
- Vite production build 성공. 전체 upstream TypeScript 검사는 기존 오류로 실패한다. 이번 Circuitiny 모듈·테스트와 변경한 breadboardSnap의 오류는 없다.
- 실제 브라우저: 3D에서 DHT22 추가·핀 정보 열기·회전·복사·붙여넣기·Undo 확인. 1kΩ 저항을 10kΩ로 수정하고 회전·복사 후 복사본 속성에서 10000 확인. 2D 전환 시 같은 두 부품의 회전 상태 확인.
- 실제 브라우저: UNO D5 배선에 경유점 추가, 기존 파형 창에 U1/5 채널 연결, Undo 확인.
- 독립 검증 예제에서 실제 AVR 컴파일·실행. 3D 버튼을 누르고 놓으면 `BUTTON_DOWN LED_ON` / `BUTTON_UP LED_OFF` 메시지와 LED·LCD 표시가 바뀐다. 3D 가변저항을 드래그하면 실제 `analogRead(A0)` 출력이 512에서 621/629로 바뀌었다.
- 실제 브라우저: ESP32의 추가 보드 옵션 창 열기·Cancel 조작 확인. 컴파일은 시도하지 않았고 검증용 보드는 제거했다.
- 사용자 작업 세션을 초기화하지 않았고, 사진 분석·유료 모델 API를 호출하지 않았다.

증거: `outputs/3d-parity/validation.vlx`, `runtime-dom.txt`, `property-dom.txt`, 화면 캡처, tests/build/types 로그.

## 지원 범위

- 전용 형상이 없는 부품은 **일반형 3D 몸체 + 실제 2D 표시 면 + 실제 핀**으로 표시한다. 치수가 검증된 CAD/STEP 모델이 아니다.
- 모든 부품의 모든 동작을 개별 하드웨어와 비교 검증한 것은 아니다. 읽을 수 없는/외부 자원으로 보호된 표시 면과 특수 캔버스 조작은 추가 어댑터가 필요할 수 있다.
- 3D 보드 추가가 해당 보드의 로컬 컴파일 지원을 의미하지 않는다. 현재 서버 컴파일은 **UNO + 기본 Arduino 코어** 범위이며 외부 라이브러리는 별도다.
- 기존 보드 추가/제거처럼 네이티브 편집기에서 이력이 없는 작업까지 새 Undo 명령으로 대체하지 않았다.
- 실제 조립·정격·기계 공차·실물 작동은 별도 검증이 필요하다. 원본 사진 분석 Circuit Graph나 KiCad로 자동 역반영하지 않는다.

배포·재설치 패치: `patches/velxio-embedded.patch`. Circuitiny MIT 고지와 Velxio AGPL-3.0 고지는 유지한다.

## LED의 점진적 밝기 변화 수정

3D가 순간 전류를 임계값으로 비교해 켜짐/꺼짐만 표시하던 경로를 제거했다. 이제 원본 2D LED 요소가 전류·PWM 시간 평균·소손 상태로 계산한 **동일한 0~1 밝기**를 3D에 전달한다. LED 몸체 색과 발광 강도가 중간 값에 따라 변한다. 초기 수정에서는 50ms 간격으로 전달했으나, 현재는 이 폴링을 제거하고 MCU 출력 이벤트를 즉시 공유한다. [현재 MCU 시간 동기화 구현·검증](mcu-led-timing.md)을 기준으로 한다.

실행 중 **LED 밝기 · D1 30%**처럼 실제 표시 값을 제공한다. 이 수치는 전류를 반영한 정규화된 표시 밝기이며 `analogWrite` 값의 백분율이나 측정된 광도와 같지 않다. 정지·누락 데이터·유효하지 않은 밝기는 어둡게 처리하고, 원본 시뮬레이터의 소손 판정도 유지한다.

관련 테스트는 **140개 / 7파일 통과**. 추가 3개는 중간 밝기 보존, 순간 전류가 0이어도 PWM 시간 평균 밝기 유지, 소손·정지·잘못된 데이터 시 꺼짐을 검증한다. 실제 생성된 UNO D5 `analogWrite` 코드도 컴파일·실행해 3D에서 0%, 28%, 30%, 61%, 63%, 70% 등 중간 값과 2D 전환을 확인했다. 새 코드로 원본 사용자 프로젝트를 덮어쓰지 않았다.

예제와 검증 증거: `outputs/pwm-brightness/validation.vlx`, `3d.jpg`, `2d.jpg`, `shared-output.json`, tests/build/types 로그. 기존 화면을 새로고침하고 밝기 조절 설계에서 실행하면 적용된다. 점멸 코드(`digitalWrite`)는 기존처럼 켜짐/꺼짐으로 동작한다.
