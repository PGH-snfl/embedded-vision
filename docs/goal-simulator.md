# 설계 목표 → 회로·코드 → 그래픽 시뮬레이터

2026-10-27 구현.

## 사용 순서

1. `bash run.sh`로 분석 앱(8766), 별도 터미널에서 `bash run_workbench.sh`로 Velxio(8768)를 실행한다.
2. 사진·영상 분석 후 ② 기능·회로에서 **이 목표로 설계 → 시뮬레이터**를 누른다. 기존 사진 분석도 사용한다.
3. 선택한 목표의 Circuit Graph, 배선, 코드가 만들어지고 새 탭에 보드·저항·LED가 나타난다.
4. **▶ Run**을 누르면 실제 AVR 컴파일 → HEX → AVR8js 가상 MCU 실행이 진행된다. LED 반응과 Serial 출력을 확인한다.
5. 배선·부품·코드를 편집하고 다시 실행하거나 `.vlx`를 저장한다. 팝업이 차단되면 분석 화면의 **Velxio 편집기 열기**를 사용한다.

| 목표 | 새로 정한 기본 동작 | 연결 |
|---|---|---|
| LED 지속 점등 | 실행 중 HIGH 유지 | UNO D5 → 220Ω → LED A, LED K → GND |
| LED 깜빡이기 | 500ms ON / 500ms OFF 반복 | 동일 |
| LED 밝기 조절 | PWM 0~255 왕복, 20ms마다 5씩 변화 | 동일 |

PWM은 빠른 점멸에서 켜져 있는 시간의 비율을 바꾸는 방법이다. [UNO 공식 핀맵](https://docs.arduino.cc/resources/pinouts/A000066-full-pinout.pdf)에서 D5의 PWM 지원과 라벨을 대조했다. LED는 기존 검토 카탈로그의 적색 WP7113ID 규격을 새 설계에 사용한다.

사진 속 DFRobot 보드의 정확한 모델은 미확인으로 유지한다. 호환 보드를 특정하지 못하면 **시뮬레이션용 UNO R3를 새로 선정**하고 원본 보드 배정을 비운다. 220Ω·적색 LED·점멸 시간은 사진에서 판독한 사실이 아니다. 이 차이는 회로 미리보기와 시뮬레이터 상단에 표시한다.

## 데이터와 실행

- `function-candidate`는 관측 후보를 USER_DEFINED 설계 목표로 저장하며 기존 가정·근거를 보존한다.
- `function.py`의 동작 계약과 `recipes.py`의 연결 계약으로 일치하는 회로만 생성한다.
- `led.py`는 같은 Graph의 D5·저항·LED 극성을 검증한 뒤 펌웨어를 생성한다.
- `workbench/export.py`는 D5→Velxio `5`, LED K→`C`로 핀 이름을 변환한다. 함수 버전이 오래됐으면 409로 차단한다.
- 원본 Graph/이미지는 보존한다. 시뮬레이션 초안에는 실물 확인을 요구하지 않지만, 별도 회로 프로젝트·KiCad 생성의 실물 부품 검토 절차는 유지한다.
- 편집 자동 저장 키에 원본 해시·분석 ID·recipe·function_version을 포함해 다른 목표의 코드가 섞이지 않게 한다.
- Velxio의 LED 표시가 대문자 D1을 ngspice의 소문자 전류 벡터와 연결하지 못하던 문제를 수정했다. 디지털 대체 상태 대신 계산된 전류로 밝기를 갱신한다. 수정 코드와 테스트는 `patches/velxio-embedded.patch`에 포함한다.

## 검증

- 프로젝트 Python 테스트 **255개 통과**: 목표 선택→회로→VLX, 오래된 목표·다른 회로 거부, 원본 보존, 실물 검토 우회 차단, 별도 설계 생성, 실제 AVR 컴파일 포함.
- simavr로 각 펌웨어를 2.5초 실행해 **D5 실제 핀 전환과 PWM 레지스터**를 검사했다. 지속 HIGH, 약 500ms 점멸, 0~250의 PWM 비교값과 1,000회 이상의 핀 전환을 확인했다. 0/255 끝점은 Arduino core가 LOW/HIGH로 처리한다.
- Velxio LED 관련 테스트 **63개 통과**, Vite 빌드 성공. 대문자 부품 ID와 소문자 SPICE 벡터를 연결하는 회귀 테스트 포함.
- 브라우저에서 사진의 목표를 선택해 회로·코드를 자동 가져오고 컴파일·실행을 검증했다. 점멸 UART ON/OFF 반복, PWM 0~255 증감과 LED 발광의 중간 밝기, 지속 점등의 LED ON 출력 및 발광 유지도 관찰했다.
- 인식 모델을 추가 호출하지 않았다. API 비용 없이 저장된 부품 관측과 결정적인 설계 규칙을 사용했다.

최종 모델 출력 지침 변경 후 자동 분석·목표 계약 테스트 45개를 추가로 통과했다.

증거: `outputs/goal-simulator/tests.txt`, `velxio-tests.txt`, `final-regression.txt`, `pwm-running.jpg`. Python 검증 대상은 프로젝트의 `tests/`다. 외부 Velxio의 전체 Python 테스트는 별도 환경과 선택 모듈이 필요해 이번 통합 검증 범위에 포함하지 않는다.

## 한계

임의의 목표/로봇/센서 코드를 생성하는 범용 설계기는 아니다. UNO 분압, LED, 버튼, 조도 센서와 병렬 LCD 목표가 그래픽 실행 경로를 지원한다. ESP32 버튼 설계는 회로 생성 경로를 유지하지만 이 로컬 UNO 컴파일 서버에서 실행하지 않는다. SPICE 모델의 LED 발광 정도는 실물 밝기의 보정된 측정값이 아니다. 실제 회로 조립·정격·오차·원래 시스템과의 기능 동등성은 별도 검증이 필요하다.

### 버튼을 누르는 동안 LED 켜기

사진에서 LED와 버튼이 식별되면 기능 후보로 표시하거나, 원하는 기능에서 직접 선택할 수 있습니다. 이는 사진 원래 동작을 확정한 결과가 아니라 새 설계입니다. UNO R3 D5 → 220Ω → LED → GND, D2 → 버튼 → GND, 5V → 10kΩ → D2 회로와 코드를 생성합니다. 10kΩ은 버튼을 놓을 때 입력이 HIGH로 유지되게 하는 풀업 저항입니다. 버튼을 누르면 입력이 LOW가 되어 LED가 켜지고, 놓으면 꺼집니다. 6mm 버튼 4개 다리를 빵판 중앙 홈 양쪽에 배치하고 내부 공통 접점 쌍을 네트 검증에 반영합니다. 실제 버튼의 접점 배열과 LED 극성, 저항값은 조립 전 확인해야 합니다. 기존 ESP32 버튼 설계는 유지하지만 해당 시뮬레이터 자동 실행은 UNO 설계에 한정됩니다. UNO 조도 센서와 병렬 LCD 예제도 지원합니다.

### 조도 센서로 LED 켜기

조도 센서 후보를 확인하고 ‘어두우면 LED 켜기’를 선택하면 UNO R3의 A0에 가상 조도 센서 AO를 연결하고, D5에 220Ω을 거쳐 LED를 연결하는 새 설계를 만듭니다. 3D에서 센서 S1을 선택하고 ‘센서·입력값 조작’을 열어 조도를 바꿀 수 있습니다. 가상 센서는 [Wokwi 모델](https://docs.wokwi.com/parts/wokwi-photoresistor-sensor)의 5V/VCC/GND/AO 인터페이스와 기본 특성을 사용하며, 어두워질 때 A0 값이 512를 넘으면 LED가 켜집니다. 조도(lux)는 밝기의 단위입니다. 기존 사용자 회로는 이전 조도 모델을 유지합니다.

이 모델은 실물 센서의 제조사 데이터시트가 아닙니다. 실제 모듈의 전원 정격과 핀 배열, 빛의 변화에 따른 AO 방향과 값을 측정하고 코드의 임계값을 조정하세요. 센서 접지나 신호선이 빠지면 아날로그 값이 떠서 불확실해집니다. 실물 부품의 동작은 검증되지 않았습니다.
