# 사진·영상 분석 모델 선택

상단 **분석 모델 · Sol ▾** 버튼에서 Sol 또는 Astra를 고른다. 새 사진·영상 입력은 선택한 모델로 분석한다. 기존 사진은 분석 패널의 **이 사진 Astra로 다시 분석**을 누른다. 선택만으로 API를 호출하지 않는다.

- Sol: 기존 기본 분석. 별도 회로 추론 작업에서는 필요한 국소 영역만 Astra 추가 검토가 가능하다.
- Astra: 사진 전체의 구성품·기능·보완 부품·실행 설계를 직접 작성한다. 다시 Astra로 추가 검토하지 않는다.
- 전체 사진·영상 분석은 기존의 엄격한 `PhotoSystemAnalysis` 응답과 부품 참조 검사를 유지한다. Astra라고 해서 국소 검토용 `FocusedReview` 응답으로 바뀌지 않는다.
- 작업과 결과의 `analysis_model`, `routing.primary`, 호출 기록에 실제 선택을 남긴다. 실행 도중 모델 변경은 거부하며 과거 계획은 삭제하지 않는다.
- 키 대기 후 재개할 때도 원래 작업의 모델을 유지한다. 선택은 작업공간별 브라우저 설정으로 저장하며 저장이 차단된 경우에도 현재 페이지에서 사용할 수 있다.
- 키 설정 여부와 계정의 모델 접근 가능 여부는 다르다. 접근 실패를 다른 모델로 몰래 재시도하지 않는다.

사진/영상 업로드 multipart 필드는 `analysis_model`이며 기본 `gpt-6.1-sol`이다. 허용값은 `gpt-6.1-sol`, `gpt-6-astra`다. 재분석 API의 JSON `model`은 선택 사항이며 생략하면 기존 작업의 모델을 유지한다. 명시적 재분석은 `retry=true`를 사용한다. 기존 사진의 모델만 바꾸는 요청은 완료된 작업을 자동 재호출하지 않는다. SaaS 큐에도 모델을 기록하고 작업자가 작업 ID와 선택 모델을 대조한다.

코드 전용 보드 전환은 기존 Sol 경로를 유지한다. 사진 분석 모델을 고르는 이번 버튼이 별도 보드 전환 기능의 코드 모델까지 바꾸지는 않는다.

검증: 모델 HTTP 요청은 MockTransport와 테스트용 응답으로 검사하며 실제 유료 API 호출이나 사진 재전송은 하지 않는다. 근거 파일은 `outputs/analysis-model-selection/`에 저장한다. [OpenAI Docs 구조화 응답](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)의 형식과 기존 서버 검증을 사용한다.

최종 확인: 관련 회귀 검사 179개와 사진 입력 페이지 번들 검사 통과. jsdom에서 버튼 선택·설정 저장·작업공간 분리·기존 사진 재분석·실제 작업 모델 표시를 확인했다. 실제 8897·8766·SaaS 8770에서 버튼과 모듈 제공을 확인하고 서버·작업자를 재시작했다. 기존 입력·분석 파일 139개 동일, 유료 모델 호출 0회. 직접 브라우저 조작은 CUA의 timeoutMs 바인딩 오류로 미검증이다.
