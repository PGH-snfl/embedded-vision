# Embedded Vision — 멀티모달 회로 계획 프로토타입 0.4

**시스템 전환:** 편집기 상단에서 UNO·Pico·ESP32·Pi 4를 선택하면 회로·배선·코드·가이드를 함께 바꿔 새 탭에서 엽니다. 원본은 보존합니다. [사용법·검증 범위](docs/system-conversion.md).

**멀티보드 워크플로우 v3:** UNO·Pico·ESP32·Raspberry Pi 4의 보드별 회로·배선·코드를 생성합니다. UNO와 Pico는 로컬 코드·회로 실행 검사를 연결했으며 ESP32·Linux Pi 실행은 전용 서비스가 필요합니다. [구현·검증 범위](docs/multiboard-workflow.md), [웹 예제](http://127.0.0.1:8897/board-workflow.html).

UNO 자동 설계는 실행 전 실제 코드·회로의 기본 입력/출력 시험을 거치며, 센서·버튼·키보드 조작과 측정된 서보 펄스의 3D 반응을 제공한다. [실행·검사 범위](docs/closed-loop-simulation.md).

**현재 공통 기준:** [모든 입력의 워크플로우](docs/common-workflow.md). 구성품 파악 → 기능 추론 → 부족한 부품 보완·데이터시트 → 회로·코드·독립 구조물 → 구조물별 장착·배선 → 편집기·그래픽 가이드 → 사용자 조작 시뮬레이션 순서를 사진과 영상에 공통 적용합니다. 실행 규칙은 `data/workflows/photo-system-v1.json`, 이후 개발 지침은 `AGENTS.md`에 저장했습니다. 아래의 이전 단계 설명과 충돌하면 이 공통 기준을 우선합니다.

새 사진·영상을 올리면 기능을 자동 추론하고, 지원하는 기능은 새 회로와 코드를 만들어 같은 탭에서 시뮬레이터를 자동 실행합니다. 거리 표시·급수 제어·장애물 회피 및 기존 LED/LCD 등 지원된 설계에 적용됩니다. 추론이 지원 범위 밖이면 임의의 다른 기능으로 대체하지 않습니다. 거리 표시 회로는 가상 초음파 센서·LCD·LED를 사용합니다. 급수 회로에서는 가변저항이 센서 입력을, LED가 펌프 명령을 대신합니다. 장애물 로봇의 모터와 전원은 편집용 시각 부품이며 별도 3D 운동 모델로 전진·회피를 확인합니다. 3D 운동은 편집한 펌웨어의 실행 결과가 아닙니다. 사진의 원래 배선·동작과 실물 제작 가능성은 별도 확인해야 합니다. [세 사진 시험과 지원 범위](docs/photo-system-evaluation-2026-11-03.md)

새 기본 흐름: **사진·영상 업로드 → 기능과 입출력 추론 → 새 부품·회로·코드 생성 → 시뮬레이터 자동 실행**. 기존 분석을 열거나 목표를 수동으로 변경한 경우에는 시뮬레이터를 직접 열 수 있습니다. 보존된 편집 초안은 자동 실행하지 않습니다. 일반 Raspberry Pi 이동 로봇은 별도의 수동 가상 운동 화면을 사용합니다. 원본 배선은 복제하지 않습니다. ③의 부품 요약은 사진 후보와 새 부품·대체 부품을 구분합니다. [목표→시뮬레이터 사용법](docs/goal-simulator.md). [부품 우선 사용 방법·검증 결과](docs/parts-first.md), [서버 키 설정](docs/model-planner.md)을 참고하세요. 실제 모델 인식 정확도와 실물 동작은 미검증입니다.

사진의 부품·배선 후보를 근거와 함께 검토하고, 확인한 회로를 KiCad·PCB·파형·코드·조립 설명으로 연결하는 로컬 웹 앱입니다. **임의의 사진에서 완전한 회로를 자동 복원하는 제품은 아직 아닙니다.** ESP32 LED/버튼과 RC 필터의 새 설계 예제에서 전체 경로를 검증했습니다.

## 실사 사진 분석 추가

상단 **실제 촬영 사진 분석**으로 그림이 아닌 실제 Arduino 촬영 사진을 분석합니다. **＋ 사진 1장 · 자동 분석**은 서버의 Sol/Astra 자동 분석으로 연결됩니다. 영상도 최대 6개 주요 프레임으로 Sol 부품 식별을 자동 실행합니다. 아래 로컬 Qwen/OCR·배선 기능은 기존 수동 검토 경로입니다. 로컬 사진 판독은 VLM으로 수행합니다. 별도 AI 분석·계획은 Sol/Astra 멀티모달 추론과 KiCad MCP 실행을 결합합니다. 전체 부품 탐색 → 부품별 확대 재검토 → OCR 문자 위치 대조로 분석합니다. 부품은 추정 후보이며, AI의 문장만으로 배선을 생성하지 않습니다. 선 끝점·사용자 핀 위치를 사용하는 별도 배선 분석이 필요합니다.

새 사진·영상 분석에는 시뮬레이터에 등록된 부품과 보드 이름을 참고 자료로 전달합니다. 발견한 부품의 **모델·인식 근거·목록 후보**를 펼치면 목록에서 찾은 후보와 배치 제한을 확인할 수 있습니다. 목록에 있다는 사실은 사진 속 모델이나 핀·정격, 시뮬레이션 동작의 검증이 아닙니다. 목록을 읽지 못하거나 일치하는 후보가 없어도 사진 분석은 계속합니다. 기존 분석에는 새 목록 참조가 없으므로 다시 분석해야 합니다.

큰 시스템 사진·영상도 ②에서 **입력 → 처리 → 출력**과 Arduino 또는 Linux Raspberry Pi 보드 추천을 추정합니다. 실행 가능한 가상 규칙이 있을 때 입력을 바꾸어 결과를 시험할 수 있습니다. 선택한 보드는 프로토타입 대상이며, 두 보드에 같은 추정 규칙을 적용하는 기능 논리 계산입니다. CPU, 회로 전압, 모터·카메라, 시간에 따른 물리 동작이나 원본과의 동등성을 검증하지 않습니다. 미지원 기능과 가정은 펼쳐서 확인합니다. 추정에 필요한 내용이 없으면 가상 규칙을 만들지 않습니다. 기존 사진은 새로운 기능 분석을 위해 다시 분석해야 합니다.

Raspberry Pi용 가상 입출력 Python 파일은 표준 Python 3에서 JSON 입력을 받아 JSON 결과를 출력합니다. GPIO 제어와 실제 센서 연결은 포함하지 않습니다. Raspberry Pi Pico는 Linux Raspberry Pi와 다른 마이크로컨트롤러 보드이며, 현재 이 경로에서 실제 Pico 코드를 컴파일하거나 실행하지 않습니다.

실제 제작용으로는 **버튼을 누르는 동안 LED 켜기** 기능을 직접 선택했을 때 Raspberry Pi 4B 회로를 추가로 제공합니다. 구체적인 부품과 핀·브레드보드 구멍이 표시된 단계별 그림, 제조사 자료, 실제 GPIO Python 코드를 확인할 수 있습니다. 사진 속 같은 종류의 부품은 후보로만 비교하고 모델과 호환성은 직접 확인해야 합니다. 이 회로는 다른 기능의 대체 회로가 아니며, 실물 조립 및 하드웨어 동작은 아직 시험하지 않았습니다. 대형 시스템 전체를 실물 회로로 자동 변환하는 기능은 지원하지 않습니다.

바퀴가 관찰된 사진에서 단순 이동 로봇 후보를 직접 선택하면 **Raspberry Pi 4B + Adafruit Motor HAT + 2륜 섀시**의 새 제안을 제공합니다. 제조사 제품을 기준으로 부품·전원·모터 배선과 조립 단계, 전진·후진·좌우회전용 실제 Pi 코드를 확인할 수 있습니다. Three.js 3D 화면은 별도로 좌우 바퀴의 가정 속도와 차폭을 이용한 운동을 보여줍니다. 3D는 Pi 코드 실행이나 전기·모터 시뮬레이션이 아니며, 모델 치수는 실측·제작 도면이 아닙니다. 원본과의 동등성, 모터 정지 전류 및 실제 하드웨어 동작은 검증하지 않았습니다. 주차·장애물 회피·자율주행·드론 목표에는 이 단순 주행 설계를 대체 적용하지 않습니다.

로봇 목표를 선택한 뒤 **회로 편집기 열기**를 누르면 기존 Velxio Arduino 시스템 편집기가 새 탭으로 열립니다. 편집기의 **운동 미리보기**를 누르면 회로를 서버에 저장·검사한 뒤 같은 탭에서 3D 운동 화면으로 전환됩니다. **회로 편집으로 돌아가기**를 누르면 기존 편집 화면을 그대로 사용할 수 있습니다. 운동 화면은 마지막으로 저장한 회로를 기준으로 하며 각 주행 명령 전에 회로 변경을 확인합니다. Pi와 HAT 등은 실제 장치를 흉내 내는 모델이 아닌 시각 부품이며, 40핀 결합은 하나의 단자로 표현합니다. 검토된 기본 연결에서만 가상 운동을 제공하고 편집한 코드는 실행하지 않습니다. 편집기 코드·시각 구조물은 편집기 프로젝트에 저장됩니다.

3D 운동 화면에서는 방향키 또는 W/A/S/D를 누르고 있는 동안 직접 주행할 수 있습니다. 화면의 방향 버튼도 길게 누를 수 있으며, 입력을 놓거나 화면에서 벗어나면 멈춥니다. 이 조작은 추정한 가상 운동을 제어하며 실제 로봇이나 편집한 프로그램을 실행하지 않습니다.

로봇 편집기에는 기본 배선용 Raspberry Pi Python 코드가 미리 입력됩니다. 코드를 확인·수정하고 복사해서 Pi의 `pi_rover.py` 파일에 붙여넣을 수 있습니다. I²C와 MotorKit 준비가 필요하며, 실제 하드웨어 동작은 시험되지 않았습니다. 배선을 바꿨다면 코드와 실제 연결을 다시 대조해야 합니다. 이 코드는 가상 운동 화면에서 실행되지 않습니다.

로봇 편집기의 **시스템 전환**은 현재 회로와 코드를 함께 검사하고 대상에 맞는 별도 편집 프로젝트를 만듭니다. Arduino를 선택하면 Uno·Motor Shield V2·좌우 모터·별도 모터 전원 및 배선을 생성하고 Arduino 코드를 함께 엽니다. Raspberry Pi C는 기존 Pi/HAT 배선을 유지하고 C 코드로 변환합니다. 결과 확인 후 **변환된 회로·코드 적용**을 누르면 같은 탭에서 새 회로가 열리며, Pi 원본 초안은 별도로 보존합니다. 제공된 2륜 로봇 코드에서 주석·서식과 명령별 출력값만 바꾼 경우와 검토된 기본 회로만 지원합니다. 그 밖의 동작 변경이나 연결은 임의로 버리지 않고 변환을 거절합니다. Arduino에서는 시리얼 명령을 사용하며 주행 중 정지 명령 처리가 최대 2초 지연됩니다. 실드와 모터는 시각 전용 부품이며 변환 코드는 실물·모터 전기 동작을 검증하지 않았습니다. [제조사 모터 전원 연결 안내](https://learn.adafruit.com/adafruit-motor-shield-v2-for-arduino/powering-motors)

편집기 도구는 작업 화면 옆에 배치합니다. 왼쪽 공통 도구줄 맨 위에 **시스템 전환**을 고정하고 저장·실행·화면 전환을 세로로 배치합니다. 코드 도구는 코드 창 옆에, 부품·배선·2D/3D·화면 맞춤은 회로 창 옆에 둡니다. 편집 화면을 가리던 상단 도구줄은 옆 도구줄로 옮겼습니다. 전환된 회로에서도 시스템 전환 버튼이 유지되며 원본 시스템을 열어 다른 대상을 선택할 수 있습니다.

그래픽 편집기 3D 화면에서 상자·원기둥 구조물을 추가하고 이동·크기·색상·회전을 편집할 수 있습니다. 구조물은 전기 핀이 없는 시각 요소이며 편집기 프로젝트 저장에 포함됩니다. 사진 기반 로봇의 3D 동작 시험에서도 구조물을 추가하고 차체·보드·배터리를 편집할 수 있고, 프로젝트·기능 목표별로 서버에 자동 저장됩니다. 주행 시 구조가 로봇을 따라 움직이지만 형상 편집은 전기 회로, 실제 제작 설계 또는 바퀴 속도·차폭 계산을 바꾸지 않습니다.

저장한 사진·영상 프로젝트는 상단 프로젝트 선택 옆의 **사진·프로젝트 삭제** 또는 **영상·프로젝트 삭제**에서 확인 후 지울 수 있습니다. 원본, 추가 사진·영상 프레임, 해당 프로젝트의 서버 분석 기록과 초안이 함께 삭제됩니다. 별도로 생성한 회로 프로젝트, 다운로드 파일, 브라우저 초안은 남습니다. 분석·작업이 진행 중이면 완료 후 다시 시도하세요. 잘못된 업로드나 저장 실패 시에는 해당 요청이 생성한 파일만 자동 정리합니다.

② **기능·회로**에서 가장 유력한 기능을 입력 → 제어 보드 처리 → 출력 흐름으로 확인하고, 지원되는 기능은 **이 기능 시뮬레이션하기**를 눌러 새 회로·코드를 엽니다. 원본 동작과 실물은 미검증이며, 추천 순위는 분석 근거와 정성적 판단에 따른 것으로 측정된 확률이 아닙니다. 추천 기능을 지원하지 않으면 그대로 안내하며 다른 기능으로 바꾸지 않습니다.

시뮬레이션 버튼 앞에는 **새 시뮬레이션에서 실행할 동작**을 별도로 표시합니다. 예를 들어 사진에서 밝기에 따른 LED 반응 방향이 미상이어도 새 회로는 ‘어두워져 A0 값이 512보다 클 때 켜짐’을 기본값으로 사용합니다. 시뮬레이터 상단에도 초기 새 설계의 동작을 표시하며, 편집한 코드에 따라 그 설명이 자동 변경되지는 않습니다.

VLM 재실행: 별도 터미널에서 `bash run_vlm.sh`. 모델 설치·실제 시험·오인식 결과는 [실사 분석 기록](docs/camera-vision.md)에 정리했습니다.

단계별 확대 분석과 보류 규칙은 [개선 기록](docs/staged-photo-analysis.md)에 정리했습니다.

```bash
bash run.sh
```

**http://127.0.0.1:8766** 을 엽니다. 현재 이 컴퓨터에 서버를 실행해 두었습니다. 종료 후에는 위 명령으로 다시 실행합니다.

다른 환경: Python 3.12, uv, KiCad 10의 CLI·표준 심볼/풋프린트·시스템 Python `pcbnew`, `libngspice.so.0`가 필요합니다.

```bash
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python -r requirements.lock.txt
bash run.sh
```

Node 빌드는 필요 없습니다. OCR 모델은 RapidOCR 패키지에 포함된 ONNX 모델을 CPU에서 실행합니다. 기존 로컬 분석은 사진을 외부로 보내지 않습니다. 새 사진·영상 업로드는 이미지/추출 프레임과 기본 메타데이터를 OpenAI API로 전송하여 부품을 식별합니다. 기본 부품 식별에는 원본 연결·배선 가설을 전달하지 않습니다.

## 먼저 해보기

화면은 **입력 확인 → 부품·문자 → 배선 추정 → 회로 검증 → 결과물** 순서입니다. 각 단계에 입력·처리·출력과 현재 확인할 항목이 표시됩니다. 분석·생성은 실행 버튼을 눌렀을 때 진행합니다. [단계별 화면 설명](docs/step-workflow.md)

1. **ESP32 전체 예제**: 설계 그래프 → KiCad 회로도 → 연결 대조 → ERC → PCB 배선 → DRC → SPICE를 실행합니다. ERC는 회로도 규칙 검사, DRC는 PCB 간격·배선 규칙 검사입니다.
2. **02 KiCad·PCB**: 실제 KiCad 출력과 검사 결과를 보고 편집 가능한 프로젝트 ZIP을 받습니다.
3. **04 코드·조립**: 코드 생성 → Arduino `.ino` 다운로드. GPIO 명령 설명과 LED 논리 동작, 단계별 연결 가이드를 확인합니다. 펌웨어 컴파일·보드 실행은 수행하지 않습니다.
4. **RC 필터 예제** → **03 파형·전류**: 두 측정 지점의 실제 ngspice 결과를 비교합니다. `transient`는 시간 변화, `ac`는 주파수 응답, `dc`는 직류 입력 변화입니다.
5. R1/C1·주파수·진폭을 바꾸면 새 버전과 파형을 저장합니다. 이전 KiCad 결과는 현재 결과에서 제외하며 다시 생성해야 합니다.
6. 설계 도우미에 `R1을 10kΩ으로 바꿔`, `차단 주파수를 1kHz로 맞춰`, `PCB 만들어`를 입력합니다. 현재는 지원 문장만 해석하는 로컬 명령 처리기입니다.

## 실제 사진·영상 검토

1. **＋ 사진**으로 PNG/JPEG를 올립니다(12 MB, 2천만 화소 이하). **＋ 영상**은 64 MB·5분 이하이며, 최대 24개 시점에서 최대 6개 주요 프레임을 선택합니다.
2. **OCR·부품 후보 분석**으로 글자를 읽고 알려진 표식의 부품 후보를 만듭니다. OCR은 이미지의 글자를 읽는 기능이며, 칩 표식만으로 개발보드 모델을 확정하지 않습니다.
3. **＋ 부품 영역**으로 누락된 부품·단자를 지정합니다. **핀 위치 지정**으로 사진 속 각 단자의 위치를 표시합니다.
4. 다시 분석하면 색상 선의 두 끝점이 지정 핀과 유일하게 대응할 때만 **INFERRED** 연결 후보를 추가합니다. 겹침·분기·가림·모호한 대응은 확정하지 않습니다.
5. **배선 추정**에서 한 장의 사진으로 가림 경로 가설을 비교하고 연결·근거를 검토합니다. 순위 점수는 정답 확률이 아닙니다.
6. **05 부품·근거**에서 정확한 모델을 확인한 근거를 입력하고 지원 카탈로그 핀을 지정합니다. 모든 생성 조건이 충족된 지원 회로만 KiCad로 내보냅니다.

## 구현 범위와 한계

| 기능 | 현재 동작 |
|---|---|
| 사진·영상·여러 각도 | 저장·프레임 선택·사진 전환. 자동 다중 시점 추적/통합은 미지원 |
| 부품 인식 | Qwen3-VL 실사 부품 후보 + OCR + 수동 검토. 실제 시험에서 오인식 확인, 정확도 미검증 |
| 배선 추론 | 색상 분리·선 중심/끝점·사용자 핀 위치로 후보 생성. 실제 사진 정확도 미측정 |
| 근거·신뢰도 | CONFIRMED/INFERRED/UNKNOWN, OCR 점수, 수정 이력. 점수는 보정된 정확도 확률이 아님 |
| 데이터시트 | 소규모 검증 카탈로그·제조사 링크·사용자 모델 확인. 범용 검색/자동 PDF 검증은 미지원 |
| KiCad | 새 설계는 MCP 회로도 생성·연결 대조·ERC. 기존 예제 CLI 경로도 유지. 실시간 GUI 편집 아님 |
| PCB | 회로도에서 내보낸 netlist로 배치·2층 배선·DRC. 지원 부품 최대 6개, 예제 중심 |
| SPICE | 실제 libngspice DC/AC/시간 해석. ESP32는 이상적 GPIO 신호원, LED는 근사 모델 |
| 웹 | 실제 심볼/선, KiCad SVG, PCB SVG, 2채널 파형, 값 수정, 전류 재생 |
| 측정 지점 | Graph·KiCad net·PCB net·SPICE node 이름 일치. 별도 프로브 패드는 미배치 |
| 코드·가이드 | ESP32 LED/버튼 및 Arduino LCD 코드와 새 연결의 핀별 설명. 실물 컴파일·업로드·작동 시험 미실행 |
| AI 도우미 | Sol 부품 식별 API, 고급 Sol/Astra 회로 추론, 검토된 설계의 MCP 실행. 실제 호출·정확도 별도 검증 |
| PCB 사진 복원 | 표면 직선 후보만 표시. 실제 trace/비아 연결 재구성·내층 복원은 미지원 |

ESP32 예제 PCB의 U1은 **4핀 외부 연결 헤더**입니다. ESP32 개발보드를 직접 꽂는 장착 풋프린트가 아닙니다. 물리 핀 `J2.1`, `J3.1`, `J3.2`, `J3.9`와 PCB 헤더 핀의 관계는 `mapping.json`에 기록합니다. 실제 보드가 ESP32-DevKitC V4인지 대조해야 합니다.

예제의 CONFIRMED는 명시한 새 설계 정의와 카탈로그 근거에 한정됩니다. 사진에서 발견한 사실로 표시하지 않습니다. ERC/DRC 통과도 실물의 모델·정격·조립·작동을 보증하지 않습니다. 미확인 연결이 있으면 생성 경로를 차단합니다.

## 구조·검증

`backend/circuit` 공통 그래프·저장·검증 → `vision` OCR/배선/프레임 → `datasheet` 카탈로그 → `kicad` 생성/검사 → `simulation` ngspice → `tutorial` 가이드. `backend/integration.py`가 웹 API를 연결하고 `frontend`는 JavaScript/SVG로 표시합니다.

`.runtime/`에 원본 이미지·SQLite 수정 이력·리비전별 산출물을 저장합니다. 원본과 기존 근거를 보존하고, 수정 충돌은 거절합니다. 기존 `signal_generator`, `ai_test` 프로젝트는 수정하지 않았습니다.

```bash
.venv/bin/python -m pytest -q
```

상세 구현·검증·남은 작업은 [통합 검증 기록](docs/integrated-prototype.md)을 보세요. 기존 M1 문서는 당시 범위의 기록입니다.

### 핀·선 끝점 검토

실제 사진에서 **문자·선 끝점 후보 찾기** → 문자 확대 → 실제 핀 위치 지정 → 선 양 끝점 대조를 진행할 수 있습니다. 자동 연결은 만들지 않으며 사용자 검토 결과도 우선 INFERRED로 저장합니다. [사용 방법과 실사 검증 결과](docs/pin-wire-review.md)를 참고하세요.

[2026-10-22 후속 검증](docs/validation-2026-10-22.md): 실사 AI 재분석, 브라우저 저장 흐름, 모호한 끝점 대응 차단 및 원본 보존 검사.

[부품별 핀 라벨·연결 제안](docs/pin-label-assistance.md): 붙어서 읽힌 문자 이름을 원문 근거와 함께 분리하고, 사용자가 지정한 핀 위치로 선 양 끝점의 대응을 제안합니다.

[사진 한 장의 가림 배선 추정](docs/single-view-wiring.md): 색상·진행 방향·굵기·간격으로 연결 가설을 만들고, 점선과 대안 후보로 표시합니다. 추가 사진 없이 동작하며 순위 점수는 정답 확률이 아닙니다. [이전 다각도 기능 기록](docs/occluded-wiring.md)은 호환용으로 보관합니다.

### UNO 임베디드 시스템 실행

③ 회로 제안의 **임베디드 시스템 시뮬레이터** 또는 생성한 회로의 ④ **임베디드 실행**을 사용합니다.
현재 UNO R3 분압 회로에서 Arduino 코드 컴파일 → simavr MCU 실행 → ADC0 입력 → UART 출력까지 검증합니다.
`bash scripts/setup_avr.sh`로 Ubuntu Jammy amd64용 도구를 프로젝트 내부에 구성할 수 있습니다.
실행 구조·검증 범위·라이선스는 [embedded-simulator.md](docs/embedded-simulator.md)에 정리했습니다.

## SaaS 모드

작업공간별 데이터 분리·별도 worker 대기열·회로/코드 서버 저장을 추가했습니다. 현재 로컬 SaaS 미리보기는 로그인 없이 기본 작업공간으로 바로 진입합니다. 계정 생성은 필요하지 않습니다.
기존 로컬 모드와 데이터를 유지하며 새 SaaS 서버는 http://127.0.0.1:8770 에서 실행합니다.

```bash
bash run_saas.sh
# 다른 터미널
bash run_saas_worker.sh
```

현재 한 호스트용 SaaS 초기 구조입니다. PostgreSQL/S3 이관, 공개 배포, 구독/결제는 아직 아닙니다.
KiCad는 SaaS 전용 격리 실행 환경을 구성하기 전까지 이 모드에서 차단합니다.
[구조·실행법·운영 확장 계획](docs/saas-architecture.md)을 확인하세요.

로그인 복구: `EV_SAAS_AUTH_ENABLED=1 bash run_saas.sh`로 API 서버를 다시 실행하세요. 기존 계정은 보존됩니다.

SaaS 모델 키 설정: `bash configure_saas_openai.sh`를 실행하고 키를 숨김 입력하세요. `.runtime/saas-worker.env`에 권한 600으로 저장되며 실행 중인 worker에 자동 반영됩니다. 파일은 기존 `.runtime/` 제외 규칙으로 Git에 포함되지 않습니다.
