# 모든 입력에 적용하는 공통 워크플로우

현재 기준: 2026-11-12, 버전 7. 사진 한 장·여러 사진·영상, 보드가 드러난 회로·외장으로 감싼 시스템 모두 같은 논리적 순서를 적용한다. 입력마다 결과 부품과 설계는 달라진다. 이전 단계의 문서는 개발 이력이며 현재 순서와 충돌하면 이 문서와 JSON 규칙을 우선한다.

초기 구성품 식별·확대 재검토에는 보드 목록, 보드 프로파일과 핀·전압·실행기 사양을 제공하지 않는다. 공통 워크플로우에 들어 있는 보드 프로파일과 참고 카탈로그의 보드 항목도 제외한다. 사진에서 관측한 보드의 이름·표식·모델 후보는 부품 목록에 기록할 수 있다. 재검토한 구성품 메모를 확정한 뒤 회로 설계 요청에만 보드 사양·부품 구현 카탈로그를 전달한다. 프로그램용 관측 목록과 설계는 마지막 통합 JSON에서 함께 받는다. 기본 분석 경로는 확대 검토 사용 여부와 관계없이 이 순서를 따른다.

사진 분석의 중간 결과는 자유 문장·표·코드 메모로 이어간다. 중간 메모마다 JSON 해석·스키마 검사를 하지 않는다. 마지막 `final_photo_json` 응답 한 개만 `strict=true`의 JSON 스키마로 받아 프로그램 데이터로 변환한다. 최종 관측 부품 ID는 재검토 메모에 있어야 하고 설계 참조·부품·핀·연결·전압·코드는 기존 검사로 확인한다. 모델의 비공개 내부 추론을 노출하는 기능이 아니라 단계별 작업 메모를 기록하는 기능이다. 응답 중단·거절·시간 초과·최종 형식 오류는 별도다.

| 순서 | 단계 | 결과 |
|---|---|---|
| 1 | 입력 정규화·영상 프레임 선택 | 좌표 기준 이미지와 입력 ID |
| 2 | 보이는 구성품 먼저 파악 | 부품·모델 후보·수량·표식·위치 목록 |
| 3 | 목록을 참고해 시스템 기능 추론 | 입력 → 제어 → 출력, 가장 유력한 기능과 대안 |
| 4 | 실행에 부족한 부품 보완 | 보드·전원·구동기·보호·배선 등 새 설계의 구체적 선정 |
| 5 | 시스템 데이터시트 작성 | 관측 부품·추가 부품·선정 규격·핀·설계 이유 |
| 6 | 회로·배선·코드 생성 | 동일 부품과 핀을 사용하는 편집 가능한 회로와 코드 |
| 7 | 외형·동작 대상 오브젝트 생성 | 앞뒤를 포함한 독립 구조물, 필요한 물통·화분·바퀴 등 |
| 8 | 구조물별 부품 장착 | 부품 → 장착 구조물 관계, 핀에 연결된 배선 |
| 9 | 편집기와 그래픽 가이드 | 조립·분해·회로 보기, 전환 애니메이션, 단계별 양쪽 연결 안내 |
| 10 | 사용자 조작 시뮬레이션 | 코드 실행, 센서·버튼·키보드 입력과 실제 출력 시각화 |
| 11 | 검사·저장 | 부품/핀/코드/장착/저장 검사와 입력·출력 동작 결과 |

## 보드별 공통 실행

[보드 워크플로우와 검증 범위](multiboard-workflow.md)를 따른다. 보드별 핀·전압·언어·실행기 정의는 `data/board-profiles.json`이며 워크플로우 해시에 포함된다. 관측 보드가 기능에 맞으면 우선 유지하고, 보드 변경 시 회로·배선·코드·시험을 함께 새로 구성한다.

## 설계 기준

원래 배선을 복제하는 것이 아니라 추론한 기능을 수행하는 새 시스템을 만든다. 사진에서 보이지 않는 원본 내부를 관측했다고 주장하지 않는다. 실행에 필요한 추가 부품·값·배치는 `DESIGN_SELECTED`(새 설계에서 선정한 값)로 구체화한다. 원본 관측 목록은 유지한다. 모델·핀·정격의 실제 지원 여부와 호환성을 검사한다. 같은 절차가 모든 시스템의 시뮬레이션 성공을 보장하지는 않으며 미지원 기능과 실패한 검사는 해당 단계의 결과로 표시한다.

사진·영상 분석은 상단 **분석 모델**에서 선택한 Sol 또는 Astra를 유지한다. 기본 경로는 **관측 메모 → 원본 분할 확대·ID별 재검토 메모 → 기능·회로 설계 메모 → 최종 통합 JSON**이다. 원본 확대는 실제 픽셀을 사용하며 최종 부품별 잘라보기는 확인용이다. 개별 후보마다 별도 JSON 재검토를 요청하던 이전 경로는 명시적 내부 비교용으로만 남긴다. 보통 AI 요청 4회이며 첫 관측의 선택적 스킬 도구 왕복이 있으면 5회가 된다. 실행당 최대 16회·720초 한도와 자동 유료 재시도 금지는 유지한다. 기존 입력은 자동 재분석하지 않는다.

데이터시트는 생성한 시스템 요약과 제조사 원본을 구분한다. 시스템 전환 시 기존 주변 부품과 동작을 유지하고, 공통 입출력 역할과 보드 규칙으로 핀·전원·배선을 먼저 확정한다. 전압 보완 부품은 규칙으로 추가하며 AI Sol은 확정된 대상 회로의 코드만 작성한다. AI 응답에는 부품·배선 변경 항목을 허용하지 않는다. 회로·코드·구조·시뮬레이션은 같은 설계를 사용한다. 시뮬레이션 결과와 단순 동작 미리보기를 구분하고 실물 검증은 사용자가 진행한다. KiCad/PCB는 별도 요청 사항이다.

## 공통 편집 규칙

- 부품을 각 구조물에 붙인다. 구조물 분해·이동·회전 시 부품과 배선 양 끝이 핀을 따라간다. 자동 장착 대상은 선택 카드에서 변경하고 저장할 수 있다.
- 조립·분해·회로 보기는 같은 프로젝트의 표시 전환이며 다시 로딩하지 않는다. 약 720ms의 전환 애니메이션을 사용한다. 사용자가 카메라를 조작하면 자동 카메라 이동은 멈춘다.
- 2D는 수직 내려보기, 3D는 같은 장면의 회전 제한 해제다. 관성 이동은 꺼둔다.
- 구조물·부품·배선은 기본 고정하고 선택 카드에서 이동을 활성화한다. 아무것도 선택하지 않았을 때 정보 카드를 띄우지 않는다.
- 핵심 입력·출력과 번호가 있는 단계는 잘 보이게 두고 근거·검증·세부 설정은 토글로 접는다. 가이드는 양 끝 연결을 한 단계로 보여준다.
- 편집기 상단 공통 도구는 시스템 전환·파일, 시뮬레이션, 작업 화면, 프로젝트 저장 카드로 묶는다. 코드·회로 전용 도구는 해당 화면 위에 두며 버튼은 40px 이상, 사진 입력 페이지는 42px 이상으로 표시하고 좁은 화면에서는 줄바꿈한다.

## 저장 위치와 적용 지점

- 기계가 읽는 규칙: `data/workflows/photo-system-v1.json`
- 공통 로더·버전/내용 해시·모델 프롬프트: `backend/workflow.py`
- 이후 개발 작업의 지침: `AGENTS.md`
- 조회: 로컬 `GET /api/workflow`, SaaS `GET /api/w/{workspace}/workflow`
- 사진·영상 자동 분석은 공통 `AutoAnalysis → inventory_plan`을 사용한다. 요청의 공통 문맥·분석 작업·분석 계획에 워크플로우 ID/버전/내용 해시를 기록한다.
- 새 회로·사진 구조 출력에는 `embeddedVision.workflow`로 같은 규칙을 전달한다. 이는 **처리 계약**이며 모든 단계가 완료됐다는 결과 보고서가 아니다.
- 기존 저장 결과는 보존한다. 규칙 저장·서버 재시작만으로 이전 입력을 유료 재분석하지 않는다. 다시 분석할 때 최신 규칙을 적용하고, 기존 편집기에는 공통 뷰어 기능을 적용한다.

검증 기록은 `outputs/common-workflow/`에 저장한다. 로봇·조광기·서보 등 구성이 다른 예제와 사진·영상 경로에서 동일한 순서와 메타데이터를 확인하며, 테스트용 모델 응답과 실제 유료 호출은 구분한다.

## 이번 적용 검증

버전 2의 실행 전 코드·회로 시험, 사용자 조작, 서보 출력과 구조물 연결, 자동 보완의 범위는 [실행·검사 설명](closed-loop-simulation.md)에 기록했다.

- 관련 Python 검사 **67개 통과**. 조광기·서보 각각을 사진·영상 업로드에 넣는 4가지 조합에서 통합 모델 요청 1회, 관측 목록 보존, 회로·코드·사진 구조 출력과 공통 버전 전달을 확인했다. 이 분석 응답은 테스트용 대체 응답이며 새 인식 정확도 평가가 아니다.
- 로컬과 SaaS 작업공간의 워크플로우 조회 API가 동일한 규칙과 내용 해시를 반환한다. 다른 작업공간에는 접근할 수 없다.
- 진행 중인 분석·작업이 없는 상태에서 기존 환경·데이터 경로를 유지해 로컬 API와 SaaS 서버·처리기에 반영했다. 기존 입력·분석 파일 139개를 보존했고 유료 모델 호출과 기존 입력의 자동 재분석은 0회다.
- 이전 로봇 사진의 새 편집기 출력에도 공통 버전을 전달하며 기존 배선 21개와 코드를 유지했다. 이는 저장 결과 재사용 검사이며 새 AI 분석·실물 검증이 아니다.
