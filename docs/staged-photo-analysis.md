# 부품별 확대 분석 개선 — 2026-10-21

## 변경 이유

사용자 Arduino UNO/LCD 사진에서 기존 단일 호출 모델은 가변저항을 놓치고, 별도 저항·전원 보드와 근거 없는 연결 8개를 제안했다. 부품 발견, 문자 판독, 연결 추론을 분리했다.

## 현재 처리 순서

1. `vision/staged.py`: 전체 사진에서 주요 외부 부품 목록과 영역을 탐색한다. 배선·핀 번호·저항값은 요청하지 않는다.
2. 배선 묶음을 부품으로 제안한 경우 제외한다. 개발보드 내부의 작은 후보는 별도 외부 부품인지 확인할 때까지 보류한다. 보류한 원본 후보와 이유는 보고서에 남는다. 이는 위치 기반 규칙이며 부품의 부재를 증명하지 않는다.
3. 각 후보 영역을 잘라 같은 모델로 다시 살핀다. 처음 제안한 이름은 재검토 프롬프트에 넣지 않는다. 판단이 불명확하거나 종류가 다르면 최초 후보와 상충된 결과를 함께 남기고 단자는 추가하지 않는다. 재검토도 AI 추론이며 독립적인 실물 검증은 아니다.
4. 전체 사진과 최대 3배 확대 영역에 RapidOCR를 적용한다. 별도 단기 프로세스가 작업 후 종료되어 문자 인식 메모리를 반환한다. 글자의 좌표를 원본 좌표로 환산한다.
5. 부품 영역 안의 OCR 문자와 정확히 일치하는 단자 라벨만 추정 후보로 남긴다. `D10` 속 `D1` 같은 부분 일치는 인정하지 않는다. 두 OCR/AI 결과가 같아도 실제 핀 번호나 전기적 기능은 확정하지 않는다.
6. AI 문장으로 배선을 생성하지 않는다. 실제 선 끝점·사용자가 지정한 핀 위치를 사용하는 기존 별도 분석 경로를 유지한다. 겹친 선과 브레드보드 내부 연결은 여전히 자동 복원하지 못한다.
7. UI에 배선 미복원, 원본 배선 제안/제외 수, 보류 후보를 표시한다. 원시 모델 응답과 필터링한 관측 결과를 구분해 보존한다.

## 데이터와 UI

- 부품 종류 `display`, `potentiometer` 추가. 기존 그래프는 그대로 읽힌다.
- 부품별 단자 라벨 제한을 4개에서 40개로 확대. 단자 수에 맞춰 웹 회로의 행 높이를 조정한다.
- 부품·문자 후보는 INFERRED, 부품 값과 실물 핀 매핑은 UNKNOWN이다.
- `report.stages`: 전체 탐색, 확대 OCR, 확대 모델의 원본 출력.
- `report.raw`: 그래프에 반영한 필터링 결과. 원본 모델 출력으로 오해하지 않도록 `raw_kind`를 추가했다.
- `report.rejected_components`: 보류 후보와 이유.
- `report.wiring`: 미복원 상태, 제안·제외·UNKNOWN 유지 개수.
- 중간 실패 시 `*-vlm-<job>-error.json`에 이전 단계와 실패 응답을 저장한다. 실패한 작업의 부분 그래프는 반영하지 않는다.
- CPU 요청 대기는 최대 600초이며 웹 작업은 비동기로 처리한다. 모델 분석과 메모리를 많이 사용하는 테스트는 순차 실행한다.

## 검증

70개 자동 테스트 통과(기존 63개 + 단계별 분석 7개). 문자 소속 영역, 정확한 토큰 일치, 낮은 OCR 점수 제외, 중복 ID, 잘못된 좌표, 보류 후보, 실패 원본 보존, 비확정 상태 유지와 기존 KiCad/SPICE 경로를 확인했다. 실제 사진의 인식 정확도는 이 테스트 숫자로 판단하지 않는다.

실사 비교 결과는 `outputs/photo-review-2026-10-21-v2/`에 별도로 저장한다. 최초 재분석은 메모리 압박 중 요청 시간 제한으로 실패했으며 회로에 반영하지 않았다. 실패 이력을 숨기지 않고 별도로 보존했다.

## 남은 한계

작은 범용 모델의 부품 위치·문자·분류 오류는 여전히 가능하다. 확대 검토는 최초 탐색에서 빠진 부품을 새로 찾는 전체 탐색을 대체하지 않는다. 부품 범위가 겹치면 문자 소속이 잘못될 수 있고, OCR가 붙여 읽은 단자 문자열은 보수적으로 누락된다. 동영상은 프레임별 처리이며 동일 부품의 자동 합치기는 하지 않는다. 사진만으로 검증된 조립 회로를 자동 생성하는 단계에는 도달하지 않았다.
