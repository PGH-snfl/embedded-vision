# 멀티모달 reasoning + structured action planner

현재 기본 흐름은 [parts-first-v1](parts-first.md): 사진·영상 → Sol 부품 식별 → 부품 검토 → 별도 새 회로·코드 → KiCad MCP입니다. 아래 focused-v2는 고급 회로 추론 경로의 설명이며 기본 업로드의 배선 추론은 수행하지 않습니다.

여기서 VLA는 로봇 구동 정책을 학습한 모델이 아니라, 이미지 판독·추론과 작업 계획을 결합한 애플리케이션 구조를 의미합니다. 실제 도구 실행 권한은 모델에 주지 않습니다.

## 구성과 경계

| 모듈 | 역할 |
|---|---|
| `backend/planner/provider.py` | Responses API, 이미지 첨부, JSON Schema 출력, 응답 완료/거절 검사 |
| `models.py` | 허용된 작업·관측 결과의 엄격한 형식 정의 |
| `service.py` | Sol/Astra 선택, 근거 ID 검사, 그래프 해시, 실행 조건 |
| `mcp.py` | KiCad MCP stdio 연결, 허용 도구 목록, 시간 초과 처리 |
| `executor.py` | 검증된 Graph를 KiCad 입력으로 변환, 연결 비교, ERC 검사 |
| `routes.py` | 계획 저장·조회·실행·다운로드 API |
| `frontend/planner.js` | 분석 → 계획 검토 → 실제 실행 화면 |

모델은 근거 요약·추정·미확인 사항과 `review_evidence` / `build_schematic`만 반환합니다. 임의의 MCP 도구 이름, 경로, 셸 명령은 받을 수 없습니다. 서버가 확인된 그래프와 기존 부품 카탈로그에서 심벌·핀·net 입력을 생성합니다. 모델이 제안한 연결이나 값은 원본 그래프에 자동 반영되지 않습니다.

## 고급 회로 추론 흐름 (focused-v2, 기존 기능)

사진 한 장을 올리면 업로드 API가 서버 작업을 예약합니다. 모델 선택·프롬프트 입력·분석 시작 버튼은 필요 없습니다. 브라우저는 진행 상태를 조회하고 결과를 자동 표시합니다. 고급 설정에서만 추가 분석 요청을 할 수 있습니다. 기존 로컬 Qwen 분석은 별도 수동 기능으로 남기며, 새 사진의 기본 경로에서는 중복 실행하지 않습니다.

키가 없으면 사진을 보존하고 `waiting_credentials`로 대기합니다. 설정 후 열려 있는 화면이 자동 재개합니다. 페이지가 닫혀 있어도 이미 시작된 분석은 서버에서 계속됩니다. 키 대기 중 페이지를 닫았다면 다시 열면 재개합니다. 서버 재시작 시 진행 중 작업은 `interrupted`로 표시하며, 과금 중복을 피하기 위해 자동 재호출하지 않습니다.

## 모델 선택

- **Sol**: 이미지 전체의 부품·배선·관측 근거를 기본 분석합니다.
- **Astra**: Sol이 지정한 `deep_review` 질문 중 검증 조건을 만족한 것만 모아서 한 번 검토합니다.
  - 경쟁하는 연결 후보, 회로 연결 충돌, 전원/신호 연결 충돌 중 하나.
  - 서로 다른 후보가 최소 2개이고, 비교 가능한 가시 근거와 구체적인 질문이 있어야 함.
  - 기존 분석 항목 번호와 실제 입력 이미지에 연결된 영역이어야 함.
  - 지정 영역이 전체 이미지의 55%를 넘으면 전체 재분석에 가까운 요청으로 보고 제외함.
  - `solvable_from_visible_evidence=false`는 추가 모델 호출 없이 미확인으로 유지함.
- 가림, OCR 실패, 빈 그래프, UNKNOWN, 낮은 confidence만으로는 Astra를 호출하지 않습니다.
- 근거·단자 참조가 잘못된 Sol 응답도 Astra로 넘기지 않고 검토 대상으로 남깁니다.
- Astra에는 **해당 영역의 잘라낸 이미지**, 선택한 분석 항목, 관련 단자/부품/근거만 전달합니다. 전체 그래프와 전체 원본 사진은 재전송하지 않습니다.
- 최대 질문 3개, 질문당 분석 항목 4개, Astra 호출 1회. Astra는 지정 항목만 갱신할 수 있고 나머지 Sol 결과를 덮어쓸 수 없습니다.
- Astra 실패·범위 이탈·항목 누락 시 Sol 결과를 유지합니다. 어느 모델도 CONFIRMED로 승격할 수 없습니다.
- 각 모델의 사용량과 지연, 검토 영역, 호출·제외 사유를 기록합니다.

이 기준은 **실측 정확도를 예측하는 분류기가 아닙니다.** `deep_review`를 선별하는 Sol의 성능과 최종 추론 정확도는 정답 데이터로 평가해야 합니다. 55%는 전체 이미지 재분석을 제한하는 구현 기준이며 실험으로 보정된 최적값이 아닙니다.

## 설정

[OpenAI API Keys](https://platform.openai.com/api-keys)에서 프로젝트용 비밀 키를 생성합니다. API 사용 한도·결제 상태도 확인합니다. 키를 브라우저나 채팅에 입력하지 마세요. 이 프로젝트에서는 아래 명령으로 숨김 입력할 수 있습니다.

```bash
cd /home/snowflower/CVR_LAB/PCB/embedded_vision
bash configure_openai.sh
```

스크립트가 키를 `.runtime/openai-api-key`에 소유자만 읽고 쓸 수 있는 권한(0600)으로 저장합니다. 키 값은 화면·셸 이력에 출력하지 않습니다. 웹의 **AI 분석·계획 → 상태 새로고침**을 누르면 서버 재시작 없이 적용됩니다. 환경변수 `OPENAI_API_KEY`도 지원하며 파일보다 우선합니다. 다른 데이터 폴더를 쓰는 서버는 스크립트에도 같은 `EMBEDDED_VISION_DATA`를 설정하세요. 키가 있더라도 모델 접근 권한과 실제 추론 정확도는 첫 요청 성공 후 별도로 검증해야 합니다.

MCP는 기존 설치된 `uvx --offline kicad-mcp-pro`를 사용합니다. 테스트한 서버는 4.4.0입니다. MCP를 이 앱용 별도 프로세스로 띄우며 작업 디렉터리를 해당 실행 폴더로 제한합니다. 프로필 full, operating_mode write를 적용하지만 클라이언트 허용 목록 밖의 도구는 호출할 수 없습니다. 원래 Codex MCP 설정은 수정하지 않습니다.

## 입력 전송과 보존

- 사진 파일은 로컬에 저장합니다. 기존 로컬 Qwen VLM 수동 분석은 외부로 전송하지 않습니다.
- **사진 업로드 시** 입력 이미지와 그래프를 OpenAI API로 전송하여 자동 분석합니다. 고급 추가 요청도 선택 이미지를 전송합니다.
- 영상은 기존 추출 프레임 최대 6장을 사용합니다. 원본 영상 직접 입력은 구현하지 않았습니다.
- 이미지는 긴 변 최대 1600 px JPEG로 변환하여 전송합니다. 미세한 마킹이 손실될 수 있으므로 UNKNOWN을 유지해야 합니다.
- Responses API `store=false`. 이는 서비스의 모든 보존 정책이 0일임을 의미하지 않습니다.
- 자동 작업 상태는 `.runtime/auto_jobs/<project>.json`에 기록합니다. 계획은 `.runtime/planner/<project>/<plan>.json`, 실행 기록은 같은 위치의 `<plan>/execution.json`에 저장합니다.

## MCP 실행 순서

1. 현재 그래프 리비전과 내용 해시를 계획과 비교합니다.
2. readiness(확정 부품·값·핀·연결 및 지원 프로필)와 모델 검토 항목을 확인합니다.
3. 실행별 새 프로젝트를 MCP로 생성합니다. 기존 회로도에 덮어쓰지 않습니다.
4. `sch_build_circuit`로 심벌과 net을 생성·저장합니다.
5. `export_netlist` 결과의 핀 연결 집합을 원래 그래프와 정확히 비교합니다.
6. `run_erc`가 명시적으로 PASS인지 확인합니다. WARN/FAIL/UNKNOWN이면 중단합니다.
7. `export_sch_svg`로 검토용 출력을 만듭니다.

같은 계획은 재실행할 수 없고 새로운 계획이 필요합니다. 실패한 실행의 기록과 파일은 보존합니다. 실행 중 그래프가 바뀌어도 해당 실행은 고정된 이전 스냅샷으로 격리되며, 응답에 stale 표시를 붙입니다.

이번 MCP 경로의 범위는 **회로도 생성·연결 대조·ERC**입니다. PCB 동기화·배치·배선·DRC는 추가 구현 대상입니다. 기존 수동 ‘설계 전체 실행’/‘회로도·PCB 생성’ 버튼과 레거시 `/agent`는 기존 CLI 경로이며 새 모델 계획 경로와 구분됩니다. ESP32 예제는 기존 설계대로 4핀 외부 인터페이스 헤더이며 DevKit 장착 풋프린트가 아닙니다.

## 자동 작업 검증 기록

`tests/test_auto_analysis.py`에서 사진 업로드 단독 실행, 중복 요청 방지, 키 대기/재개, 재시작 중단 표시, 리비전 충돌, 단순 미확인 비승격, 잘라낸 이미지 크기, 상위 모델의 범위 밖 수정 차단을 검사합니다. 웹에서는 테스트 서버에 API로 사진을 업로드하고 자동 결과 표시와 고급 설정이 기본 접힘인 것을 확인했습니다. 브라우저 자동화의 파일 선택은 확장 프로그램의 file URL 접근 권한이 없어 검증하지 못했습니다. 실제 사용자의 일반 파일 선택 기능과는 별개의 자동화 권한 문제입니다.
