# 구성품 목록에서 시작하는 시스템 설계

2026-11-04부터 새 사진·영상 분석은 아래 순서로 진행한다.

1. 보이는 구성품의 종류·모델 후보·표식·수량·위치를 식별한다.
2. 관측 목록을 저장하고 화면에 먼저 표시한다.
3. 저장된 목록을 근거로 시스템 기능과 입력·처리·출력 후보를 추론한다.
4. 기능에 부족하거나 가려진 부품을 별도의 보완 목록으로 작성한다.
5. 관측 목록·기능·보완 부품·확인할 사양을 시스템 데이터시트로 정리한다.
6. 데이터시트가 준비되면 지원하는 회로·배선·코드를 생성하고 시뮬레이터로 전달한다.

화면의 네 단계는 `사진 입력 → 구성품 목록 → 기능·부품 보완·데이터시트 → 회로·시뮬레이션`이다.

## 분석 경계

- Sol의 첫 요청은 `Inventory`만 반환한다. 기능을 먼저 정하지 않으며 숨겨진 필수 부품을 관측 목록에 넣지 않는다.
- 두 번째 요청은 저장된 `observed_inventory`와 해시를 받고 `SystemReasoning`을 반환한다. 이 출력에는 관측 목록을 수정하는 필드가 없다.
- 보완 부품은 `required_parts`에만 기록한다. `INFERRED`는 새 설계에 필요하다는 추정이며, 사진 내 존재 여부는 `UNKNOWN`이다.
- 각 보완 부품은 근거 관측 부품 ID, 해당 기능 후보 ID, 수량, 용도, 추가 이유, 확인할 사양을 가진다. 없는 ID 참조·중복 ID·확정 상태는 거부한다.
- 제조사 자료, 핀 배치 안내, 예제, 시뮬레이터 문서를 구분한다. 생성한 데이터시트는 시스템 부품 요약이며 제조사 원본이나 실물 검증 결과가 아니다.

## 중간 저장과 실패 처리

관측 목록은 후속 모델 호출 전에 같은 분석 ID로 저장한다. 기능 분석 중에도 목록을 조회할 수 있다. 후속 분석 실패·서버 재시작 시 목록을 보존하고 회로 생성은 차단한다. 유료 모델 호출을 자동으로 반복하지 않는다.

`component_datasheet`는 관측 목록의 해시와 보완 부품을 저장한다. `GET /api/projects/{project}/inventory/{plan}/datasheet`에서 조회하며 `?download=true`로 JSON을 저장할 수 있다. 화면의 **시스템 데이터시트 보기**에서는 관측 → 기능 → 보완 → 새 회로 사양 순서로 보고 HTML로 저장할 수 있다.

## 회로와 시뮬레이션

새 분석에서 기능이 추론되고 핵심 부품이 사진에 없으면 지원 회로의 명시적인 새 부품으로 보완할 수 있다. 예를 들어 LCD만 관측돼도 표시 기능에 맞는 새 UNO 보드를 선정할 수 있다. 추가 부품은 사진에서 발견한 것으로 기록하지 않는다.

회로·코드 생성은 기존 검토된 회로 규칙과 거리 표시·급수 제어·장애물 회피 시제품을 사용한다. 임의의 모든 기능이나 부품 조합을 설계·검증하는 기능은 아니다. 급수 시제품의 가변저항·LED 대체와 로봇의 가상 운동 같은 지원 한계도 유지한다.

현재 로컬 서비스에 적용했다. 기존 사진의 이전 분석은 보존하고 자동 재호출하지 않는다. 새 순서로 처리하려면 **이 사진 자동 분석 다시 시작**을 사용한다.

## 검증 기록

`outputs/components-first/`에 자동 검사, 실제 사진의 중간 관측 목록, 최종 분석·데이터시트, 생성 회로와 컴파일·실행 결과를 저장한다. 실제 API 결과와 모델을 대체한 회귀 검사는 구분한다.
