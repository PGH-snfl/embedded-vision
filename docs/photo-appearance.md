# 사진 기반 내부 3D 구조

사진 분석의 `photo_structure`를 기능 회로와 별개로 버리지 않고 모든 새 기능 편집기에 전달한다. 단일 `photo_system` 호출에서 구성품, 기능, 실행 설계, 외형을 함께 작성하며 추가 모델 호출이나 파일 내보내기는 필요 없다.

- 외형: 상자·원통·구, 사용자 외곽선의 두께 생성, 슬롯/구멍, 색상이 다른 세부 조각. 다리·발판·서보·센서·케이블을 구분한다. 보행 로봇을 일반 2륜 템플릿으로 분류하지 않는다.
- 공유: `photoGeometry.ts`가 편집기와 운동 미리보기의 실제 형상을 함께 만든다. 원통의 회전 전 부모 비율을 보정하여 얇은 센서판 위 원형 센서가 타원으로 찌그러지지 않게 한다.
- 화면: 처음에는 사진 구조를 크게 보여준다. `사진 구조 / 회로·배선` 버튼은 표시와 카메라만 전환한다. 부품·배선·코드는 유지하며 조립 가이드가 핀을 지목하면 회로 보기로 전환한다. 구조를 선택해 기존 이동 도구로 수정할 수 있다.
- 저장: 기존 브라우저 초안·작업공간 저장·되돌리기 경로를 사용한다. 사진 형상이 전기 핀이나 연결을 생성하지 않는다.
- 접근: 분석 결과의 `사진 구조 열기`, 또는 `/photo-editor.html?project=...&plan=...`. 실행 설계가 없어도 형상 편집은 가능하며, 이 경우 실행 버튼을 비활성화한다.

## 실제 입력 검증

입력은 `Downloads/arduino robot`의 600×600 카메라 사진이다. 저장된 입력의 정규화 PNG 해시와 일치함을 확인했다. 프로젝트 `8c79a35f61934203ac442f1c5a7126cc`, 새 계획 `6d7f4c135beb4790a05ccbf251cffdac`에서 Sol **1회 호출**로 외형 16개, 아두이노 회로, 배선 21개, 코드를 생성했고 코드 컴파일에 성공했다. 기존 입력과 이전 계획은 보존했다.

발판 두 개의 외곽선·슬롯, 검은 몸통 판, 금색 지지대, 구동부, 전면 센서, 보호관이 생성됐다. 결과와 렌더링은 `outputs/photo-appearance/actual-plan.json`, `actual-workbench.json`, `actual-three-view.png`에 있다. 렌더링은 제품에서 쓰는 형상 생성 함수의 오프라인 결과이며 브라우저 스크린샷이 아니다. 브라우저 자동화는 `timeoutMs` 연결 오류로 실제 GUI 검증을 수행하지 못했다.

## 정확도 범위

이 기능은 사진 외형을 편집 가능한 입체로 근사한다. 원본과 픽셀 단위로 일치하는 모델·텍스처 복원은 아니다. 한 장에서 알 수 없는 깊이·뒷면·실측 치수는 가정이며, 세부 곡면·케이블 경로·재질은 단순화된다. 외형 공유가 보행 관절·접촉·균형에 대한 물리 시뮬레이션을 추가하지는 않는다. 제어 코드 컴파일과 실제 동역학 검증은 구분한다.

## 회귀 확인

Python 사진 구조·단일 호출·기능 구현·자동 시제품 테스트 33개 통과. 추가 구조 저장·조립·외장 관련 27개 통과(일부 중복). 네이티브 편집기·구조·조립 테스트 29개 통과. TypeScript 전체에는 기존 오류 359개가 있으며 이번 변경으로 추가된 오류는 0개다. 패치 24개를 원본에 순서대로 적용해 작업 트리와 일치하는지 확인했다.
