# 구조물 내부 배치와 배선

지원 범위는 현재 Pi/HAT 2WD 제안과 이 제안을 Uno/Motor Shield로 전환한
프로젝트다. 새 보드를 임의로 선택하거나 단자 연결과 코드를 바꾸지 않는다.

`assemblyPlanner.ts`는 사진에서 추정한 차체 판·플랫폼·케이스·바퀴에 실제
등록된 표시 모델을 장착한다. 펼쳐 놓은 구조물은 사진의 상대 위치를 기준으로
조립 위치에 모으며, 이전 위치는 `embeddedVision.assembly.previousParts`에
보관한다. 첫 조립 이후의 재계산은 사용자가 수정한 구조 위치와 크기를 사용한다.
`이전 배치 복원` 또는 편집기 되돌리기로 복원할 수 있다.

1. 보드 적층: Pi/HAT는 GPIO40의 X/Z 위치를 일치시킨다. Uno/Shield는 공개
   Eagle의 U$1 A4/A5/5V/GND@2 패드와 기존 Uno 표시 모델에 맞춰 적층한다.
   I²C·전원 연결은 같은 논리 net으로 보존하고 점퍼 대신 헤더 결합으로 표시한다.
2. 모터: 보이는 바퀴 축에 맞춰 회전한다. 다른 모터는 새 2WD 설계의 대칭
   장착을 제안하며 보이지 않는 바퀴 형상은 만들지 않는다.
3. 전원: 케이스의 추정 내부 공간을 먼저 사용하고, 여유가 없으면 판 위의
   장착 후보를 찾는다. 몸체 외에 단자 인출 공간도 검사한다.
4. 후보 비교: 보드 위치·방향과 전원 위치·방향의 후보를 검사한다. 부품 간
   겹침, 구조물 간섭, 판 경계, 케이스 포함 관계로 후보를 제외한 뒤 단자 간
   맨해튼 길이로 순위를 매긴다. 상위 후보 12개는 실제 우회 경로까지 비교한다.
5. 배선: 단자에서 부품 밖으로 나오는 경로, 직각 경로 후보, 장애물 면을 잇는
   3D 탐색을 사용한다. 길이와 굴곡을 줄이고 기존 배선과의 근접에도 비용을
   준다. 경로를 찾지 못하면 UI에 미해결 이유를 표시하고 관통 선을 그리지 않는다.

`evAssembly`는 표시 위치·회전·장착 대상과 기준 native 좌표를 저장한다.
원래 2D 핀 ID와 연결은 유지된다. 3D에서 부품을 드래그하면 native XY 변화가
표시 위치에 반영되고 경로를 다시 계산한다. 장착 대상의 평면 이동도 따라간다.
크기·회전·기구 변경 후에는 `배치·배선 최적화`로 다시 계산한다.

내부 보기는 차체와 외장을 반투명하게 표시한다. 운동 미리보기에는 편집기의
제품 메시와 케이블을 직접 직렬화해 전달하므로 대체 상자로 바뀌지 않는다.
외부 이미지 URL, 사용자 셰이더와 과도한 그래픽 데이터는 받지 않는다.
그래픽은 브라우저에서만 전달하며 서버 회로 저장에는 넣지 않는다.

## 검증 범위

- 사진 구조의 표시 기준 길이 220 mm는 가정이며 실제 치수는 UNKNOWN이다.
- 케이스 내부 공간, 벽 두께 2 mm, 상부 서비스 개방, 절연 간격 2 mm,
  적층 간격 12/16 mm는 새 설계의 가정이다. 고정 홀·기구 고정·커넥터 높이와
  실제 케이스 인출구는 실물 검토가 필요하다.
- Pi의 높은 USB/Ethernet 블록은 실제 배치에 맞춘 보수적인 별도 상자로
  검사한다. Pi/HAT의 예정된 헤더 결합은 허용하는 장착 관계다.
- 전역 최적해, 실제 기계 공차/강도/방열, 배선 전류 용량이나 전기 안전을
  보증하지 않는다. 표시 길이는 가상 치수의 경로 합계로, 실물 절단 길이가 아니다.
- 운동 화면의 구조 편집은 기존과 같이 시각 모델 편집이다. 회로 부품의
  장착 관계와 배선을 함께 바꾸려면 회로 편집기에서 수정하고 다시 실행한다.
