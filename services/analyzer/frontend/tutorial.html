§01

편집기 한 명령으로 시작

기본 설치는 편집기만 준비하고 편집기 홈을 엽니다.

Ubuntu 22.04 · x86_64

사용 순서

64비트 Intel/AMD PC의 데스크톱 Ubuntu 22.04, curl과 인터넷이 필요합니다. 부족한 시스템 패키지는 sudo 비밀번호를 요청할 수 있습니다. Python·Node·편집기·UNO 컴파일러를 자동 준비합니다. 분석용 영상·OCR 패키지와 분석 서버는 기본 설치에 포함하지 않습니다.

다운로드 → 편집기 설치 → 홈 열기
curl -fsSL https://raw.githubusercontent.com/PGH-snfl/embedded-vision/main/install.sh | bash

설치 위치는 ~/embedded-vision입니다. 첫 다운로드·빌드에는 시간이 걸립니다. 실행한 터미널을 열어 두고 종료할 때 Ctrl+C를 누르세요. 기존 파일은 자동 초기화하지 않습니다.

다시 실행

사용 순서
편집기만 실행
cd "$HOME/embedded-vision" && bash services/editor/start.sh

편집기 홈: http://127.0.0.1:8768/. 루트의 bash start.sh도 같은 동작입니다.

직접 Git으로 받기

사용 순서
직접 설치
git clone https://github.com/PGH-snfl/embedded-vision.git "$HOME/embedded-vision" && cd "$HOME/embedded-vision" && bash start.sh

이미 설치한 경로에 다시 clone하지 마세요. Windows/macOS/ARM은 이 설치기로 검증하지 않았습니다.

§02

편집기 홈에서 프로젝트 선택

사진 입력 없이 내장 예제 또는 저장한 프로젝트로 시작합니다.

아두이노 편집기 열기 → 회로·코드 편집 → 실행

사용 순서
  1. 편집기 홈에서 아두이노 편집기 열기 →를 누릅니다.
  2. 보드·부품·배선과 코드를 확인합니다. 작업 화면 → 코드 함께 보기로 코드 영역을 펼칩니다.
  3. 시뮬레이션 → ▶ 실행을 누르고 버튼 입력과 LED 출력을 확인합니다.
  4. 편집 후 ↓ 프로젝트 저장으로 .vlx 파일을 내려받습니다.

프로젝트 파일 불러오기는 저장한 .vlx를 엽니다. 보드별 예제에서 UNO는 로컬 실행을 지원하고 다른 보드는 전용 실행 환경이 필요합니다.

기본 편집과 UNO 예제는 API 키 없이 실행됩니다. 사진 분석을 자동 시작하지 않습니다. 편집 내용은 같은 브라우저의 초안과 다운로드 파일로 보관하세요.

아래는 동작 흐름 설명도이며 실제 화면 캡처가 아닙니다.

직접 조작하고 출력 확인

예제별로 준비물부터 실행까지

사용 순서

홈의 아두이노 따라 하기 예제에서 LED 깜빡이기, 밝기 조절, 버튼 LED, 조도 센서 자동 조명, LCD 표시 중 하나를 고르세요. 가이드와 함께 열기 → ① 준비물 → ② 배선 → ③ 실행 확인 순서로 따라갑니다. 부품 다리·점퍼선 양 끝을 그림과 3D 핀 강조로 안내합니다. 확인한 동작을 직접 체크하고 코드 해설·변경 도전을 펼칠 수 있습니다.

§03

선택 사항: 별도 분석기 연결

사진·영상 분석이 필요할 때만 다른 터미널에서 분석기를 시작합니다.

분석기는 별도 설치·실행

사용 순서
분석기만 실행
cd "$HOME/embedded-vision" && bash services/analyzer/start.sh

분석기 주소는 http://127.0.0.1:8766/입니다. Node·AVR·편집기를 빌드하지 않고 전용 Python 환경을 준비합니다. 분석 결과 .vlx를 편집기 홈에서 불러오거나 기존 직접 열기 기능을 사용합니다.

분석용 API 키 숨김 입력

사용 순서
별도 터미널에서 키 설정
cd "$HOME/embedded-vision" && bash services/analyzer/configure_openai.sh

키는 .runtime/openai-api-key에 소유자만 읽도록 저장합니다. OPENAI_API_KEY 환경변수가 우선합니다. 키 값을 대화·소스·HTML에 넣지 마세요. 입력 이미지와 영상 프레임의 외부 AI 분석에는 비용이 발생할 수 있습니다. 키 설정이나 재시작만으로 자동 재분석하지 않습니다.

편집기 AI 코드 작성용 키
편집기 키 설정
cd "$HOME/embedded-vision" && bash services/editor/configure_openai.sh

기본 저장 위치는 .runtime/editor/openai-api-key입니다. 기존 공용 키도 호환해서 읽습니다. 편집·UNO 실행에는 키가 필요하지 않습니다.

§04

분석기: 사진·영상과 구성품 확인

관측한 부품 목록을 먼저 만든 뒤, 그 목록을 근거로 시스템의 기능을 추론합니다.

① 입력 → ② 구성품 목록

사용 순서
  1. 사진 입력 · 자동 분석 또는 영상 입력을 선택합니다.
  2. 사진은 PNG/JPEG, 최대 12MB입니다. 보드·센서·구조물 전체가 잘 보이는 이미지를 사용하세요.
  3. 왼쪽 번호에 따라 구성품 목록으로 이동합니다.
  4. 목록의 부품명·수량·위치와 실제 사진을 비교합니다. 필요한 근거·확대·검토 정보는 토글로 펼칩니다.

사진과 영상에서 추출한 프레임은 OpenAI API에 전송됩니다. 서버에 저장한 입력은 입력 삭제 기능으로 지울 수 있습니다.

확대·재검토가 하는 일

사용 순서

전체 이미지에서 후보를 찾고 원본 분할 확대에서 ID별로 재검토하며 누락·중복을 점검합니다. 중간 분석은 자유 문장·표·코드 메모로 이어가고, 마지막 통합 결과만 JSON으로 받습니다. 최종 부품별 잘라보기는 확인용 이미지입니다.

처음 분석에는 대상 보드 정보를 강제로 주지 않습니다. 관측 목록을 확정한 다음, 설계 단계에서 보드별 핀·전압·언어 규칙을 적용합니다.

각 단계의 시간·오류·근거를 확인할 수 있습니다. 확대해도 사진에 없던 내부가 관측 사실이 되지는 않습니다.

§05

분석기: 기능·부품 보완과 데이터시트

원본 배선을 그대로 복제하기보다 같은 기능을 수행하는 새 회로를 구체적으로 설계합니다.

③ 기능·부품 보완 → 데이터시트 → 설계 목표

사용 순서
  1. 관측 부품을 바탕으로 나온 기능 후보와 가장 가능성이 높은 후보를 확인합니다.
  2. 실행에 필요한데 사진에서 보이지 않는 부품은 새 설계의 추가 부품으로 선정합니다.
  3. 원하는 기능 후보를 선택합니다. 자동 선택된 새 설계가 준비되면 편집기로 바로 이동할 수 있으며, 수동으로 열 때는 회로·시뮬레이터 열기 →를 누릅니다.
  4. 3단계 오른쪽의 시스템 데이터시트 보기 버튼에서 부품 목록·핀·전원·설계 설명을 확인합니다.

여기서 만드는 데이터시트는 프로젝트의 시스템 요약입니다. 제조사 원본 데이터시트와 구분합니다. 부품 후보·관측 정보·새로 선정한 값은 서로 다른 출처로 기록됩니다.

자동 이동되어 중간 분석을 확인하지 못했다면 편집기 상단의 ← 사진 분석으로 돌아오세요. 사진 분석 화면의 왼쪽 ①~④ 단계에서 구성품·기능·데이터시트를 확인할 수 있습니다.

CONFIRMED 검증된 정보INFERRED 추론한 정보UNKNOWN 확인하지 못한 원본 정보

새 회로의 부품·핀·저항값은 선정할 수 있습니다. 그 선정값을 사진 속 원본의 확인된 사실로 표시하지 않습니다.

§06

회로·코드와 3D 편집기

편집기 홈의 예제·프로젝트 파일 또는 분석기의 회로·시뮬레이션에서 엽니다.

회로·배선·구조물 보기

사용 순서
  1. 회로·보드·빵판과 각 핀에 연결된 배선을 확인합니다.
  2. 회로 영역의 2D 보기 / 3D 보기를 누르면 같은 장면에서 수직 내려보기와 입체 보기를 전환합니다.
  3. 사진 구조물이 생성된 프로젝트에서는 조립 보기 / 분해 보기 / 회로·배선으로 내부 부품을 확인합니다. 일반 LED 예제에는 이 버튼들이 나오지 않습니다. 장착 부품과 배선 끝이 구조물의 움직임을 따라갑니다.
  4. 부품·구조물을 클릭하면 작은 선택 카드가 나옵니다. 이동 활성화를 누른 뒤 드래그하고 이동 완료로 고정합니다. 배선은 선택하면 조작점이 활성화되며 끝점을 드래그합니다. 헤더 결합 배선은 별도 상태로 표시됩니다.

선택하지 않은 상태에는 정보 카드를 띄우지 않습니다. 핀 위에서 빵판의 같은 전기적 연결선과 연결 부품을 확인하세요.

코드와 그래픽 조립 가이드

사용 순서

상단 작업 화면 → 코드 함께 보기로 코드 영역을 엽니다. 좁은 화면에서는 코드 편집으로 표시됩니다. 생성된 소스·언어·보드 핀을 확인하고 편집합니다. 코드 번역 도구는 버튼으로 펼칩니다. 코드 전용 도구는 코드 영역, 회로 전용 도구는 회로 영역에 있습니다.

회로 영역의 단계별 조립 가이드를 누릅니다. 연결할 양 끝을 한 단계로 안내하고 3D 연결 위치 확대로 위치를 확인합니다. 단계 그래픽과 편집기 포인터를 함께 보고 연결하세요. 포인터는 부품을 덜 가리키도록 대각선으로 표시합니다.

사진에서 만든 구조물은 기능·외형 확인용 근사 3D 오브젝트입니다. 숨겨진 내부나 실물 치수의 정밀 복원 결과가 아닙니다.

§07

실행하고 직접 조작하기

화면의 움직임, 보드 코드 실행, 전기 회로 계산의 검증 범위를 구분해 확인합니다.

시뮬레이션 → ▶ 실행 → 조작·동작 검사 → 보드 출력 보기

사용 순서
  1. 상단 시뮬레이션 카드에서 시뮬레이션 → ▶ 실행을 누릅니다. 자동 실행되어 ● 실행 중이면 다시 누를 필요가 없습니다. ■ 정지로 멈춥니다.
  2. 코드 준비 중…이 끝나는지 확인하고, 오류는 코드 영역의 실행 로그를 펼쳐 봅니다.
  3. 같은 카드의 입력·출력 → 조작·동작 검사를 펼칩니다. 예제 버튼은 누르고 있기 또는 Space 키로 조작하고, 센서가 있는 설계는 슬라이더를 사용합니다. 표시되는 조작은 설계에 따라 다릅니다.
  4. 입력·출력 → 보드 출력 보기와 회로 영역에서 설계에 연결된 출력을 확인합니다. LED·LCD·서보·급수 환경 등은 해당 부품과 실행 모델이 있는 설계에서 확인할 수 있습니다.
  5. 로봇 설계는 실행 버튼이 ▶ 운동 미리보기로 바뀔 수 있습니다. 이 경우 화면의 키보드/컨트롤러로 방향과 정지를 확인하며 보드 코드 실행 결과와 구분합니다.

UNO 경로는 로컬 AVR 컴파일과 AVR8js 실행을 사용합니다. 지원 회로는 ngspice로 전압·전류를 계산합니다. 파형은 Test Point(측정 지점)의 이름으로 비교합니다.

결과확인하는 것확인하지 못하는 것
코드 실행지원 보드의 컴파일·핀 출력·시간 변화모든 외부 드라이버와 실제 전력 특성
전기 시뮬레이션지원 소자 모델의 전압·전류·파형실물 열·공차·모델에 없는 현상
기능·운동 미리보기사용자 입력에 대한 가상 동작드론의 실제 비행 안정성·로봇의 실제 접촉 물리

모든 사진이 자동으로 완벽한 실행 시스템으로 변환된다고 보장하지 않습니다. 지원하지 않는 실행기는 성공으로 표시하지 않습니다. 최종 조립·실물 동작은 사용자가 검증합니다.

§08

시스템 전환과 지원 범위

편집기 상단 프로젝트 → 시스템 전환을 누르고 열린 창에서 대상 보드를 선택합니다.

주변 부품과 기능을 유지해 보드 변경

사용 순서

변환은 기존 부품과 역할을 유지하면서 대상 보드의 전원·핀·전압 조건에 따라 회로와 배선을 먼저 구성합니다. 그다음 AI가 확정된 회로에 맞는 코드를 작성합니다. AI가 코드와 함께 하드웨어를 마음대로 바꾸는 경로가 아닙니다.

필요한 전압 보완 부품은 규칙으로 추가합니다. 전환 결과의 핀·전원·언어·실행 요구사항을 확인하세요. AI 코드 작성은 API 키와 크레딧이 필요합니다.

설계 프로필코드이 설치의 실행 범위
Arduino UNOArduino C++로컬 컴파일·실행 지원

프로필이 등록돼 있다는 것은 그 보드의 실제 에뮬레이터가 이 설치에서 실행됐다는 뜻이 아닙니다. 최신 원본은 board-profiles.json입니다.

§09

공개 소스와 개인 작업 데이터를 분리합니다.

작업 저장과 종료

사용 순서

편집기의 파일·저장 도구에서 프로젝트를 저장하거나 .vlx 파일로 내려받습니다. 로컬 편집 내용은 브라우저 저장과 파일 저장을 구분하세요. SaaS 작업공간 저장은 별도 구성입니다.

편집기 프로젝트는 .runtime/editor/, 기존 분석 입력·결과는 .runtime/에 남습니다. 종료하려면 실행한 터미널에서 Ctrl+C를 누릅니다. 종료는 저장 데이터를 삭제하지 않습니다.

공개 저장소에는 사용자 사진·동영상·분석 기록·키·가상환경·설치된 의존성을 포함하지 않았습니다.

사용 순서

컴파일·설치 실패

사용 순서

bwrap 오류: 운영체제의 격리 실행 설정을 확인하세요. 설치기는 컴파일 격리를 끄지 않습니다.

다른 운영체제: 현재 자동 설치는 Ubuntu 22.04 x86_64 전용입니다. Windows/macOS/ARM/다른 Ubuntu 버전은 검증하지 않았습니다.

다운로드·빌드 오류: 인터넷·디스크 여유·패키지 오류를 확인하고 같은 명령을 다시 실행하세요. 이미 완료한 설치 단계는 재사용합니다.

§11

서비스별 개발 구조

기본 개발 우선순위는 편집기입니다. 공용 회로와 데이터만 공유합니다.

소스 소유 디렉터리

사용 순서
디렉터리역할
services/editor회로·배선·코드·3D 편집, 컴파일, 편집기 패치

각 서비스는 자체 app.py·실행 스크립트·Python 환경을 갖습니다. 두 개의 독립 저장소로 나누지는 않았습니다. 기존 분석 프로젝트의 로봇 동작 미리보기는 분석기 API를 추가로 사용할 수 있습니다. 회로 편집·UNO 실행은 분석 서버 없이 동작합니다.
