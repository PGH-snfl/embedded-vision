§01

한 명령으로 시작

처음에는 설치를 진행하고, 준비가 끝나면 사진 입력 화면을 브라우저로 엽니다.

Ubuntu 22.04 · x86_64

처음 한 번

데스크톱 Ubuntu 22.04의 64비트 Intel/AMD PC가 자동 설치 대상입니다. curl과 인터넷 연결이 필요합니다. 부족한 시스템 패키지는 sudo 비밀번호를 요청할 수 있습니다. Node.js·Python·편집기·UNO 컴파일러는 자동 준비합니다. KiCad는 기본 실행에 필요하지 않습니다.

다운로드 → 설치 → 화면 열기
curl -fsSL https://raw.githubusercontent.com/PGH-snfl/embedded-vision/main/install.sh | bash

설치 위치: ~/embedded-vision. 처음에는 대용량 의존성을 내려받고 빌드하므로 시간이 걸립니다. 이후에는 설치 결과를 재사용합니다. 터미널을 열어 둔 채 사용하고 Ctrl + C로 두 서버를 함께 종료하세요.

실행 전에 스크립트 확인하기

이 명령은 공개 저장소의 설치 스크립트를 실행합니다. 내용을 먼저 확인하려면 install.sh, bootstrap.sh를 읽으세요. 기존 설치가 있으면 덮어쓰거나 자동 업데이트하지 않고 다시 실행합니다.

예제 열기 → 보드별 공통 워크플로우 → Arduino UNO R3

무료 예제
  1. 사진 입력 화면의 상단 예제 둘러보기 카드에서 예제 열기를 누릅니다.
  2. 보드별 공통 워크플로우를 선택합니다.
  3. Arduino UNO R3 카드의 회로·코드·시뮬레이터 열기 ↗를 누릅니다.

§03

사진 AI 분석 연결

사용자의 API 키와 해당 모델을 호출할 수 있는 계정·크레딧이 필요합니다.

키를 숨김 입력으로 저장

AI 분석 필요
새 터미널에서 API 키 설정
cd "$HOME/embedded-vision" && bash configure_openai.sh
  1. 키를 붙여넣고 Enter를 누릅니다. 입력 문자는 화면에 표시되지 않습니다.
  2. .runtime/openai-api-key에 소유자만 읽도록 저장합니다.
  3. 웹 화면에서 상태를 갱신한 뒤 사진을 입력합니다. 키 설정만으로 사진을 자동 재분석하지 않습니다.

이미 내보낸 OPENAI_API_KEY 환경변수가 있으면 그 값이 우선합니다. 별도 데이터 경로를 쓰면 키 설정 명령에도 같은 EMBEDDED_VISION_DATA를 지정하세요.

키와 모델 접근이 실패할 때

401: 키 확인. 403/404: 모델 접근 권한 또는 모델 ID 확인. 429: 사용 한도·잔액·요청 제한 확인. 현재 기본 모델 ID는 gpt-6.1-sol, 심화 모델은 gpt-6-astra입니다. 공개 API 계정에서 접근 가능하다고 보장하지 않습니다. 선택 가능한 모델은 backend/planner/selection.py와 서버 오류를 함께 확인하세요.

§04

사진·영상 입력과 구성품 확인

관측한 부품 목록을 먼저 만든 뒤, 그 목록을 근거로 시스템의 기능을 추론합니다.

① 입력 → ② 구성품 목록

사용 순서
  1. 사진 입력 · 자동 분석 또는 영상 입력을 선택합니다.
  2. 사진은 PNG/JPEG, 최대 12MB입니다. 보드·센서·구조물 전체가 잘 보이는 이미지를 사용하세요.
  3. 왼쪽 번호에 따라 구성품 목록으로 이동합니다.
  4. 목록의 부품명·수량·위치와 실제 사진을 비교합니다. 필요한 근거·확대·검토 정보는 토글로 펼칩니다.

사진과 영상에서 추출한 프레임은 OpenAI API에 전송됩니다. 서버에 저장한 입력은 입력 삭제 기능으로 지울 수 있습니다.

확대·재검토가 하는 일

사용 순서

전체 이미지에서 후보를 찾고 원본 분할 확대에서 ID별로 재검토하며 누락·중복을 점검합니다. 중간 분석은 자유 문장·표·코드 메모로 이어가고, 마지막 통합 결과만 JSON으로 받습니다. 최종 부품별 잘라보기는 확인용 이미지입니다.

처음 분석에는 대상 보드 정보를 강제로 주지 않습니다. 관측 목록을 확정한 다음, 설계 단계에서 보드별 핀·전압·언어 규칙을 적용합니다.

각 단계의 시간·오류·근거를 확인할 수 있습니다. 확대해도 사진에 없던 내부가 관측 사실이 되지는 않습니다.

§05

기능·부품 보완과 시스템 데이터시트

원본 배선을 그대로 복제하기보다 같은 기능을 수행하는 새 회로를 구체적으로 설계합니다.

③ 기능·부품 보완 → 데이터시트 → 설계 목표

사용 순서
  1. 관측 부품을 바탕으로 나온 기능 후보와 가장 가능성이 높은 후보를 확인합니다.
  2. 실행에 필요한데 사진에서 보이지 않는 부품은 새 설계의 추가 부품으로 선정합니다.
  3. 원하는 기능 후보를 선택합니다. 자동 선택된 새 설계가 준비되면 편집기로 바로 이동할 수 있으며, 수동으로 열 때는 회로·시뮬레이터 열기 →를 누릅니다.
  4. 3단계 오른쪽의 시스템 데이터시트 보기 버튼에서 부품 목록·핀·전원·설계 설명을 확인합니다.

여기서 만드는 데이터시트는 프로젝트의 시스템 요약입니다. 제조사 원본 데이터시트와 구분합니다. 부품 후보·관측 정보·새로 선정한 값은 서로 다른 출처로 기록됩니다.

자동 이동되어 중간 분석을 확인하지 못했다면 편집기 상단의 ← 사진 분석으로 돌아오세요. 사진 분석 화면의 왼쪽 ①~④ 단계에서 구성품·기능·데이터시트를 확인할 수 있습니다.

CONFIRMED 검증된 정보INFERRED 추론한 정보UNKNOWN 확인하지 못한 원본 정보

새 회로의 부품·핀·저항값은 선정할 수 있습니다. 그 선정값을 사진 속 원본의 확인된 사실로 표시하지 않습니다.

§06

회로·코드와 3D 편집기

④ 회로·시뮬레이션에서 기존 아두이노 시스템 편집기를 엽니다.

회로·배선·구조물 보기

사용 순서
  1. 회로·보드·빵판과 각 핀에 연결된 배선을 확인합니다.
  2. 회로 영역의 보기·도구 → 위/입체 보기를 누르면 같은 장면에서 수직 내려보기와 입체 보기를 전환합니다.
  3. 사진 구조물이 생성된 프로젝트에서는 조립 보기 / 분해 보기 / 회로·배선으로 내부 부품을 확인합니다. 일반 LED 예제에는 이 버튼들이 나오지 않습니다. 장착 부품과 배선 끝이 구조물의 움직임을 따라갑니다.
  4. 부품·구조물을 클릭하면 작은 선택 카드가 나옵니다. 이동 활성화를 누른 뒤 드래그하고 이동 완료로 고정합니다. 배선은 선택하면 조작점이 활성화되며 끝점을 드래그합니다. 헤더 결합 배선은 별도 상태로 표시됩니다.

선택하지 않은 상태에는 정보 카드를 띄우지 않습니다. 핀 위에서 빵판의 같은 전기적 연결선과 연결 부품을 확인하세요.

코드와 그래픽 조립 가이드

사용 순서

상단 작업 화면 → 코드 함께 보기로 코드 영역을 엽니다. 좁은 화면에서는 코드 편집으로 표시됩니다. 생성된 소스·언어·보드 핀을 확인하고 편집합니다. 코드 번역 도구는 버튼으로 펼칩니다. 코드 전용 도구는 코드 영역, 회로 전용 도구는 회로 영역에 있습니다.

회로 영역의 단계별 조립 가이드를 누릅니다. 연결할 양 끝을 한 단계로 안내하고 3D 연결 위치 확대로 위치를 확인합니다. 단계 그래픽과 편집기 포인터를 함께 보고 연결하세요. 포인터는 부품을 덜 가리키도록 대각선으로 표시합니다.

사진에서 만든 구조물은 기능·외형 확인용 근사 3D 오브젝트입니다. 숨겨진 내부나 실물 치수의 정밀 복원 결과가 아닙니다.

§07

실행하고 직접 조작하기

화면의 움직임, 보드 코드 실행, 전기 회로 계산의 검증 범위를 구분해 확인합니다.

▶ 시뮬레이션 실행 → 조작·동작 검사 → 보드 출력 보기

사용 순서
  1. 상단 시뮬레이션 카드에서 ▶ 시뮬레이션 실행을 누릅니다. 자동 실행되어 ● 실행 중이면 다시 누를 필요가 없습니다. ■ 정지로 멈춥니다.
  2. 코드 준비 중…이 끝나는지 확인하고, 오류는 코드 영역의 실행 로그를 펼쳐 봅니다.
  3. 같은 카드의 조작·동작 검사를 펼칩니다. 예제 버튼은 누르고 있기 또는 Space 키로 조작하고, 센서가 있는 설계는 슬라이더를 사용합니다. 표시되는 조작은 설계에 따라 다릅니다.
  4. 보드 출력 보기와 회로 영역에서 설계에 연결된 출력을 확인합니다. LED·LCD·서보·급수 환경 등은 해당 부품과 실행 모델이 있는 설계에서 확인할 수 있습니다.
  5. 로봇 설계는 실행 버튼이 ▶ 운동 미리보기로 바뀔 수 있습니다. 이 경우 화면의 키보드/컨트롤러로 방향과 정지를 확인하며 보드 코드 실행 결과와 구분합니다.

UNO 경로는 로컬 AVR 컴파일과 AVR8js 실행을 사용합니다. 지원 회로는 ngspice로 전압·전류를 계산합니다. 파형은 Test Point(측정 지점)의 이름으로 비교합니다.

결과확인하는 것확인하지 못하는 것
코드 실행지원 보드의 컴파일·핀 출력·시간 변화모든 외부 드라이버와 실제 전력 특성
전기 시뮬레이션지원 소자 모델의 전압·전류·파형실물 열·공차·모델에 없는 현상
기능·운동 미리보기사용자 입력에 대한 가상 동작드론의 실제 비행 안정성·로봇의 실제 접촉 물리

모든 사진이 자동으로 완벽한 실행 시스템으로 변환된다고 보장하지 않습니다. 지원하지 않는 실행기는 성공으로 표시하지 않습니다. 최종 조립·실물 동작은 사용자가 검증합니다.

주변 부품과 기능을 유지해 보드 변경

사용 순서

변환은 기존 부품과 역할을 유지하면서 대상 보드의 전원·핀·전압 조건에 따라 회로와 배선을 먼저 구성합니다. 그다음 AI가 확정된 회로에 맞는 코드를 작성합니다. AI가 코드와 함께 하드웨어를 마음대로 바꾸는 경로가 아닙니다.

필요한 전압 보완 부품은 규칙으로 추가합니다. 전환 결과의 핀·전원·언어·실행 요구사항을 확인하세요. AI 코드 작성은 API 키와 크레딧이 필요합니다.

작업 저장과 종료

사용 순서

편집기의 파일·저장 도구에서 프로젝트를 저장하거나 .vlx 파일로 내려받습니다. 로컬 편집 내용은 브라우저 저장과 파일 저장을 구분하세요. SaaS 작업공간 저장은 별도 구성입니다.

업로드·분석 결과와 키는 기본 .runtime/에 남습니다. 종료하려면 실행한 터미널에서 Ctrl+C를 누릅니다. 종료는 저장 데이터를 삭제하지 않습니다.

공개 저장소에는 사용자 사진·동영상·분석 기록·키·가상환경·설치된 의존성을 포함하지 않았습니다.

사용 순서
